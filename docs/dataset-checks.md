# 数据集完整性与一致性检查

检查规则：dataset-consistency/0.1；审核与复验：dataset-review/1。更新：2026-11-06。项目试行规则，待评审。

## 1 范围

核对已明确交付范围的数据包：文件是否齐全，同一记录的文件和配套表是否对应，同一个体及同组记录的采集信息是否一致。来源是华山 SOP 中数据完整性与一致性的需求；以下计算口径是本项目首版实现，不代表医院验收或已发布标准。

文件原件不修改。不执行真实身份鉴定、信号质量评分、影像配准、去标识化或完整 BIDS 合规校验。这里的“个体一致性”指已声明受试者编号下的资料对应关系。

## 2 流程与模块

```text
本地数据包 + 独立应有清单 + 明确比较组
                    ↓
D01 文件完整性：应到/实到、大小、指纹、读取结构
                    ↓
D02 个体一致性：编号对应、通道、单位、采样率、事件
                    ↓
D03 数据集一致性：同组配置、表结构、重复记录线索
                    ↓
D04 审核与复验：说明影响、登记处理、修正后对比
                    ↓
按个体汇总 → 保存报告与本次规则
```

与单记录 M01–M09 并列使用。文件齐全不等于内容一致，内容一致也不等于信号质量合格。

## 3 输入要求

应有清单在检查前固定，说明选择了哪些受试者、会话、记录及配套文件。当前目录中现有的文件不能自动充当完整性标准。

每份记录需明确：记录 ID、主文件、受试者、会话、模态、原始/派生状态、比较组，以及配套通道表、受试者表、事件表、JSON 的相对路径。配套表须列入应有清单。没有会话用明确的 `none`；没有要求的表保持缺省，不生成虚假内容。

JSON 的继承顺序须显式给出；后项覆盖前项。软件不把原始记录的 JSON 自动套在派生数据上。秒时间和样本索引分开配置，样本索引的 0/1 起点未知时保留未知。

## 4 检查词条

| 模块 | 检查项 | 一致的条件 | 缺项或差异处理 |
| --- | --- | --- | --- |
| D01 | 文件及结构 | 指定文件存在，大小/指纹与所提供依据一致，读取结构有效 | 缺件、指纹差异列冲突；读取器不支持列未评；不完整 BrainVision 采样帧列冲突 |
| D02 | 编号对应 | 文件和表的受试者、会话、任务、采集、运行编号无矛盾；所选对象在对应表中唯一存在 | 缺失/重复编号列冲突；未提供表列未评；全队列表中的未选对象不算本地缺件 |
| D02 | 通道对应 | 通道表有 name/type/units，名称唯一非空；名称集合与文件头一致 | 集合不同列冲突；仅顺序不同列复核；按名称配对，不按行号强行对齐 |
| D02 | 物理单位 | 原始文件单位与通道表一致，µV/μV/uV 规范为同一单位 | nV 与 uV 标记为单位标注差异（内部状态 conflict），需核对标定和导出说明；未声明列复核，不静默补单位；辅助非电压通道允许 n/a |
| D02 | 采样率 | 文件头、通道表及所声明 JSON 的采样率对应 | 常规容差为相对 1e-7 或绝对 1e-6 Hz；BrainVision 另允许半微秒采样间隔舍入；超出列冲突 |
| D02 | 时长 | 有双时钟时比较表示的样本数，允许约一个样本的端点差 | 不可读或未声明列未评；不通过截断数据消除矛盾 |
| D02 | 事件 | 所需列存在，时间为有效数值、时长非负，终点在记录范围内；索引通道存在 | 负起点复核，重叠允许；n/a 未评；超界冲突；未知索引起点只作宽界检查 |
| D02 | 个体内重复记录 | 同一受试者、会话、比较组的通道、单位、采样率、参考一致 | 只有一份记录或字段不足列未评；原始/派生混组停止比较；不同植入期应分组 |
| D03 | 同组配置 | 按组声明决定是否要求通道布局、单位、采样率、参考一致 | 合法差异在方案中明确允许；不从多数数据自动推定正确配置 |
| D03 | 配套表结构 | 同组通道表列集合一致 | 可选列差异列复核，缺表未评 |
| D03 | 重复记录线索 | 检查主信号文件 SHA-256 是否重复 | 相同内容列复核；不据此判定同一受试者或造假 |

事件索引起点未知时，首版检查宽界 0 至 N+1（N 为样本数）。超界行保留原始行号并要求核对端点约定；软件不裁剪事件。该宽界不是对来源索引规范的确认。

## 5 比较组

每组必须显式声明四个开关：`same_channels`、`same_rates`、`same_units`、`same_reference`。不同模态、原始和派生状态混入同组时，停止该组比较。

当前公开样例的头皮 EEG 按原始/派生分组，分别核对固定导联配置。不同患者的 ECoG/sEEG 允许通道数和名称不同；同一患者、会话、组内的重复记录仍核对通道配置。不要求不同植入患者拥有相同的电极位置。

比较发现的是声明信息的差异，不判断哪份记录一定正确。缺少参考等依据时标“未评”，不能以多数表内容填补缺失值。

## 6 报告与复验

报告保留范围、应到/实到、受试者与记录数、比较组、每项状态、受影响记录、相对文件路径、测量值、规则版本及本次冻结清单。内部状态为：一致、冲突、待复核、未评、不适用。界面将具体原因写成“记录暂时无法读取”“单位标注不一致”等，避免仅展示状态码。

`conflict` 表示资料或结构与本次检查要求不相符，涵盖不同性质的问题，不是统一的信号质量等级。单位标注不同本身不能证明实际波幅标定错误；是否存在数值或转换错误，须结合标定系数及来源记录核验。信号未运行、条件不足而未评、已检出的资料问题应分别报告。

不把这些状态折算为 0–100 信号分，也不自动给出医院的 pass/conditional/block。模块“已完成”表示执行完成，不能替代问题结论。

后台保存每次独立结果，服务重启时将未结束任务标为中断。报告含原始相对文件名及受试者编码；未实施敏感字段清除，分享前须核对。

### 6.1 D04 审核与复验

D01–D03 完成后，对资料不符、待核对及未评项记录人工意见。处理方式为“需整改、限定用途、登记跟踪、已说明差异”；同时记录判断依据、影响或允许用途、下一步和负责人。程序结果保持原样，不因为登记了意见就改成通过。

结论须显式确认：有需整改项时为“需整改后复验”；否则待处理项须全部有意见，有用途限制时为“限定用途使用”，其余为“本次范围内已审核”。即使程序没有发现问题，也不会自动确认审核。上述结论是本地项目处理结论，不是医院的验收等级；填写人自行声明，尚无身份认证或电子签章。

每次保存新增审核版本，禁止覆盖旧版本。修改意见会清除该次最终结论，需重新确认。复验绑定上次检查及当时的审核版本；只有规则、范围和检查要求一致，且同一项目此次明确检查为一致，才能记为“复验已消除”。删掉检查、缺少证据或改变范围不能算问题消除。证据未改变的意见可继承，最终结论不继承。

报告包括当前结论、处理数量、逐项意见、复验变化和追溯信息，支持 HTML 与 PDF。资料审核与记录级信号分数分别保留；本轮仍重新运行整份资料检查，尚未实现只重算受影响记录。

## 7 依据与验证边界

华山 SOP-05 v0.2 为需求材料，原件保留于本地，不随公共仓库分发。BIDS 的通道、记录说明与事件字段用于理解输入语义；自定义事件表通过显式映射适配，不冒充 BIDS 标准表。

- [BIDS EEG 文件定义](https://bids-specification.readthedocs.io/en/stable/modality-specific-files/electroencephalography.html)：通道表、采样率、单位及记录说明。
- [BIDS 事件定义](https://bids-specification.readthedocs.io/en/stable/modality-agnostic-files/events.html)：onset/duration 语义；允许事件重叠与记录前事件。

已用固定公开子集 ds003555 v1.0.1（2 人、12 记录）和 ds003029 v1.0.7（3 人、7 记录）验证执行。真实结果可能有冲突；这不证明所有规则已被专家认可，也不覆盖全部电生理格式。
