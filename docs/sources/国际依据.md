# 头皮 EEG 质控平台：国际依据与报告顶层设计

核查日期：2026-10-28（Asia/Tokyo）。范围：头皮 EEG；未读取患者数据，未改网站或算法。以下分别标记已发布指南/规范和平台建议，不把建议写成既有验证结果。

**结论：报告首先应说明“记录了什么、在什么条件下记录、哪些检查适用、哪些证据支持质量判断”。通道数及类型、采样率、滤波、参考、电极布局、年龄/状态/任务都有国际一手依据；但不同依据的约束对象和要求等级不同。应以场景配置组织规则，不能给所有 EEG 套用同一电极数、采样率或质量分数。**

## 2. 最容易误用的数值及术语

| 核实位置 | 准确含义 | 平台建议（我们的设计，不是指南原条款） |
|---|---|---|
| IFCN/ILAE 2023 §2.4、§3.2.1、Table 3（期刊pp.110、112） | 常规/睡眠临床场景：可行时建议25电极IFCN布局；否则10–20可接受。25是在通常19个10–20记录电极基础上增加6个颞下电极 | 单列“电极数”“实际采样通道数”“EEG通道数”“辅助通道数”；不把接地/未单独采样的参考计作记录通道，不以64通道研究数据或4导睡眠EEG套用这一临床完整布局要求 |
| 同文Table 3、§3.2.3（pp.112–113） | 此场景最低采样率256 Hz；0.5–70 Hz明确是EEG**显示滤波**推荐 | 保留原始采样率和目标分析带宽；显示、采集硬件滤波、离线处理滤波分别记录。不能为了“达标”把原始文件永久裁成0.5–70 Hz |
| 同文§3.3.1（p.114） | 建议常规20分钟、睡眠30分钟，不含准备；可按预期临床收益调整 | 只对完整临床检查作对应时长提示；研究片段/导出示例需写明完整记录与分析区间，不按总时长判退 |
| ACNS G1 §1.1（官方PDF p.1） | 16个同时记录通道为其一般临床场景最低数；常需增加其他生理通道 | 不能把“16通道”与IFCN“25电极”当作同一指标直接比较 |

## 3. 报告字段：依据要求与平台字段分开

下表“依据”只描述原规范；“平台显示”均为本项目建议。BIDS的REQUIRED仅约束相应BIDS对象，不自动变成所有源文件的拒收条件。

| 报告内容 | 一手依据及原要求等级 | 平台显示/校验建议 |
|---|---|---|
| 通道数、类型、单位 | BIDS EEG：分类通道计数RECOMMENDED；`channels.tsv`本身RECOMMENDED，若提供则`name/type/units`列REQUIRED，名称唯一、类型大写。ACNS G7 Technical Description要求交代电极数及布局 | 总通道+EEG/EOG/ECG/EMG/触发/其他分别计数；列表、文件与用户标注一致性；未识别类型独列，不能全部作为EEG计算 |
| 采样率、工频 | BIDS：`SamplingFrequency`、`PowerLineFrequency` REQUIRED；偏离主采样率的通道SHOULD另记。ACNS G4要求记录采样设置 | 显示原始/当前采样率、是否重采样和各通道例外；工频记录来源，不能只凭峰值认定地理工频 |
| 滤波与参考 | BIDS：`EEGReference`、`SoftwareFilters` REQUIRED；`HardwareFilters` RECOMMENDED；单通道参考/截止频率/陷波列OPTIONAL。COBIDAS §3.2、§4.3–4.4要求充分说明采集和离线处理 | 三层分离：采集硬件、已执行数字处理、当前显示；分别展示原参考、重参考方式/参与通道、当前显示导联；未知信息显式标记 |
| 布局和位置 | BIDS：`EEGPlacementScheme`、`EEGGround` RECOMMENDED；若提供`electrodes.tsv`，必须配`coordsystem.json`。ACNS G7要求记录布局的增加、特殊电极及偏离 | 展示10–20/10–10/自定义、位置来源（实测/模板/未知）；通道名可解析不等于坐标已实测；无可信布局不输出假空间结论 |
| 年龄、状态、任务 | ACNS G1 §3.1、G7 History/Technical Description：年龄、相关临床背景和意识状态；COBIDAS §2.3–2.4：人口学与任务/静息睁闭眼。BIDS：`TaskName` REQUIRED，任务描述/指令RECOMMENDED；`participants.tsv`的`age`是RECOMMENDED，并非强制 | 年龄或适当年龄分组、清醒/困倦/睡眠及其时间段、睁闭眼、任务/条件、事件来源；不知道便不启用依赖它的生理比较。研究QC副本以匿名标识关联，不照搬临床模板的姓名/病历号 |
| 时长、分段与事件 | BIDS：记录时长/连续类型RECOMMENDED；COBIDAS设计和采集章节强调任务事件时序和同步 | 分开报告总时长、实际分析区间、有效样本/间断、各条件试次数；事件同步仅按有证据的精度陈述，不能凭事件存在认定已同步 |
| 质量结果与处理来历 | BIDS通道`status/status_description`是OPTIONAL；未知可用`n/a`，坏通道宜说明噪声。COBIDAS预处理Table 3建议记录识别标准、参数、删/修复方法、剩余试次或静息有效时长 | 逐通道/时间段证据、阈值及配置版本、处理前后数量、失败/不适用/未运行原因、人工复核；“未评估”不可折算为“好” |

逐项规范：[BIDS EEG元数据与通道表](https://bids-specification.readthedocs.io/en/stable/modality-specific-files/electroencephalography.html)、[BIDS participants规范](https://bids-specification.readthedocs.io/en/stable/modality-agnostic-files/data-summary-files.html#participants-file)、[ACNS G7正式全文pp.328–330](https://www.acns.org/UserFiles/file/Guideline7-GuidelinesforEEGReporting_v1.pdf)、[COBIDAS实验设计§2.3–2.4](https://cobidasmeeg.wordpress.com/2018/08/07/experimental-design-reporting/)、[COBIDAS预处理Table 3](https://cobidasmeeg.wordpress.com/2018/08/07/preprocessing-and-processing-reporting/)。

## 4. 临床诊断报告与数据QC报告的边界

ACNS G7的成人常规临床报告有五部分：病史、技术说明、EEG描述、印象、临床关联。技术说明覆盖电极数/布局及偏离、记录条件和意识状态；后面的波形解释和临床关联需要结合个体背景。此结构不能被一个自动质量评分替代。[ACNS G7，pp.328–330](https://www.acns.org/UserFiles/file/Guideline7-GuidelinesforEEGReporting_v1.pdf)

本项目建议将数据QC报告组织为：

1. **记录概况**：匿名记录标识、来源及解析器版本、模态/使用场景、年龄/状态/任务、完整记录与本次分析区间。
2. **采集与通道配置**：各类型计数、单位、采样率、布局、原参考、滤波和设备信息；每字段标注来自文件、采集说明、人工确认还是推断。
3. **数据完整性**：读取/长度/时间轴/单位/重复命名等确定性问题；与“未提供可选信息”分开。
4. **质量证据**：可定位到通道及时间的异常、统计值和判据、波形/频谱视图、已评估覆盖范围；保留人审修改及理由。
5. **分析适用性**：针对预定用途列出通过、受限、无法评估及原因；结果应注明有效时长/试次和空间覆盖，而不只给总分。
6. **处理与复核**：处理顺序、软件/参数版本、删除/插值/重参考清单、剩余数据；自动结果与人工判断分别记录。

这是平台设计提案，不是国际指南规定的六段格式。临床“异常”可以是高质量记录到的真实脑活动；数据“质量可用”也不意味着临床“正常”。缺乏年龄/状态/任务时，可做文件和技术检查，但应暂停依赖其解释的生理正常性判断。单纯幅度大、频谱异常、左右不对称或尖锐活动不应未经复核就标为伪迹并自动删除。

## 5. 建议的实施优先级与规则模型

**P0（先补报告合同）**：通道分类和计数；单位/采样率；三层滤波；原参考/重参考；布局来源；任务/状态；分析区间；每个检查的适用性与运行状态。上述字段缺失不统一判退，而应使依赖该字段的结论标成“无法评估”。

**P1（使结果可复查）**：电极/通道表、异常时间线、实际波形与频谱、工频和参考问题的证据、处理留痕、人工确认、有效数据量。先能回答“为什么标记”，再考虑跨记录排序。

**P2（分场景验证）**：分别验证常规临床、研究静息/任务、少导睡眠等配置；对真实脑活动保留与伪迹检出的损益作独立评估。在未验证前不宣称统一质量分数能预测所有下游分析效果。

建议每条规则保存 `source/version/section/level/scope/required_inputs/decision/limitation`。其中 `level`区分规范REQUIRED、指南推荐、本项目工程规则；`decision`区分满足、不满足、未知、不适用、未执行。任何汇总同时显示检查覆盖率和未评分原因。以上数据结构与状态集合均属本项目建议，不能标成BIDS已有字段或指南原文。
