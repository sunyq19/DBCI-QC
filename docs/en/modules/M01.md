# M01 Data intake and structure checks

Module guide · Applicable implementation: Workbench 1.0.0rc2 · Document version: 0.3

This module uses format adapters to extract technical information, check companion files and convert usable voltage signals to common analysis units. Successful reading does not confirm modality or acceptable signal quality.

[Related specification](/en/standards#51-m01-data-intake-and-structure-checks) · [Next: M02 Data characterization and check plan](/en/standards/modules/M02)

## 1 Purpose and scope

Current intake covers continuous EDF/EDF+, BDF, BrainVision triplets, continuous EEGLAB SET with embedded data or a companion FDT, and single-file Raw FIF. Multi-file recordings are uploaded together as ZIP archives, retaining same-directory references.

EDF+D, BDF+D, annotation-only EDF, epoched EEGLAB, split FIF and non-Raw FIF are outside this continuous-check implementation. The current BrainVision adapter explicitly rejects duplicate channel names. Readers may retain non-EEG channels and available technical information for other modalities; only confirmed scalp EEG enters the corresponding quality checks.

## 2 Inputs and prerequisites

M01 is mandatory and has no preceding computation dependency. Input is one file or a ZIP with a unique recording entry point. Required members must be present; references must not address locations outside the package, remote resources or symbolic links.

Technical information is read before modality and channel roles are confirmed. Original indices identify channels. Formats supporting duplicate names retain separate identities; adapters without such support must explicitly reject them rather than silently rename channels. Extensions, name inference and reader default types do not replace provenance checks.

## 3 Processing and methods

### 3.1 Format adaptation and structural checks (available)

The entry format selects a reader. File structure, recording length, sampling information, channels and companion relationships are checked and exposed through a common description. Format reading is separate from signal algorithms.

EDF/BDF checks cover header length, record integrity and digital/physical endpoints, with reading by native sampling stream. BrainVision VHDR references its waveform and marker files. EEGLAB's SET data field identifies embedded data or an external FDT. FIF retains declared signal types and the source sample origin.

### 3.2 Units and voltage calibration (available)

EDF/BDF uses digital and physical ranges for calibration. Other adapters use format declarations, resolution or reader calibration. BrainVision format-default units are distinguished from explicitly declared units. Selected analysis signals must be reliably convertible to V.

Non-voltage units retain their meaning and are not relabeled V. Missing file range endpoints do not produce invented endpoint-plateau evidence. These are numerical reading checks, not device metrology, noise or electrode-impedance tests.

### 3.3 Provenance, time and annotations (available)

The primary file and required companions receive separate fingerprints. Source channel names, original indices, native sampling rates, sample origins and time offsets remain traceable. A nonzero FIF `first_samp` is not reset to source sample zero; selection times in seconds remain relative to the first sample of the file.

Extractable annotations are retained as source information, not automatically used as quality ground truth or registered M07 event tables. EEGLAB boundaries are represented as continuous segments; deleted sections are not silently joined into uninterrupted acquisition.

Currently, only the FIF adapter extracts source-declared high-pass and low-pass settings. These declarations do not verify the actual filter transfer function. Unavailable acquisition-filter histories in other formats remain unknown.

## 4 Outputs and interpretation

The main evidence file is `M01_input.json`. Its `header` uses a common structural-check representation across formats.

| Output | Content and units | Interpretation |
| --- | --- | --- |
| `header` | Structural checks, channel declarations and issues | Successful reading does not establish absence of artifacts |
| `streams` | Native rate in Hz, sample count, origin and duration in s | Retains clocks and continuous segments; does not imply resampling |
| `source_files` | Primary file, required companions and individual fingerprints | Identifies the complete input, not just the entry file |
| `reader_id`, `reader_version`, `backend_version` | Adapter and dependency versions | Evidence for reproducing reader behavior |
| `annotations` | Annotations extractable from the format | Source events, not confirmed artifact labels |
| `metadata.modality_evidence` | Declared channel types and confirmation requirement | Technical evidence, not a diagnosis or final modality determination |
| `warnings` | Structural, interpretation or capability limits | Review against the channels and methods actually selected |

Insufficient conditions and warnings retain specific reasons. If safe reading, reliable selected-signal calibration or fingerprint consistency fails, corresponding downstream values must not be interpreted.

## 5 Configuration

| Constraint | Current implementation | Nature |
| --- | --- | --- |
| Upload size | At most 512 MiB per file or ZIP request | Platform resource limit, not a recording quality standard |
| Multi-file references | Unique entry point; same-directory regular files | No guessed filenames or out-of-package reads |
| EDF/BDF channel count | 1–4096; positive samples per record | Structural checks of these format adapters |
| Analysis units | V; display may use µV | Conversion based on verifiable calibration |
| Implicit processing | No automatic resampling, re-referencing or cross-stream alignment | Method-specific processing of copies is recorded separately |

These are intake settings, not industry signal acceptance limits. Selection and execution limits are in M02. A readable format does not ensure that every detector's bandwidth and duration conditions are met.

## 6 Validation and limitations

Eight representative EDF default selections have evidence of pointwise agreement with an independent reader. The new small BDF, BrainVision, EEGLAB and FIF examples have upstream fingerprints, technical headers and reading results checked. These engineering examples are not a natural-artifact accuracy benchmark.

All five formats have completed the actual HTTP intake-to-report flow without failed modules. Some methods remain unassessed because of duration, bandwidth or missing information. This verifies workflow connectivity, not applicability of every method or validated detection accuracy.

The BDF and BrainVision fixtures last only 1 s and 7.9 s, respectively, so some methods cannot assess them. The FIF example mixes MEG and EEG and cannot be treated entirely as scalp channels. EEGLAB tutorial events are not technical-quality ground truth.

Headers do not guarantee complete or correct acquisition descriptions. Missing coordinates, filter history, reference and context remain unknown. Reader format defaults must be distinguished from explicit declarations. Downstream computation preserves source files and rechecks provenance consistency.
