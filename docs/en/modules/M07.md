# M07 State and event checks

Module guide · Applicable implementation: Workbench 1.0.0rc1 · Document version: 0.4

This module maps registered sleep stages, task events or clinical events to the current selection, retaining sources, original times and coverage issues. Labels provide recording context; they are neither signal-quality ground truth nor detector inputs.

[Related specification: 5.7](/en/standards#57-m07-state-and-event-checks) · [Prerequisite: M02](/en/standards/modules/M02) · [Summary: M08](/en/standards/modules/M08)

## 1 Purpose and scope

The module applies to external event tables with explicit time bases, label meanings and provenance. Three registered TSV formats are supported: sleep stages, task events containing `event_name`, and clinical events.

Readers may extract embedded annotations, but do not automatically register them as M07 event tables or discover stage/event files in the same directory. Users can explicitly map existing source annotations in an input revision, confirm their task, sleep-stage or clinical-event meaning, and generate a fingerprinted derived TSV. External companion tables still require a supported format and separate registration. The relationship between original annotations and derived tables must be retained.

M07 checks timing and coverage, not diagnostic correctness, staging accuracy or task performance. Without registered annotations, the module is skipped; normal recordings or absence of events are not inferred.

## 2 Inputs and prerequisites

M02 supplies selection onset and duration in the original recording, sampling rate and starting sample. Annotation times must already be converted to seconds relative to the same recording origin. Absolute times, milliseconds and another device's clock must not be mixed directly.

Each annotation source declares a format and file location. The table's SHA-256 and the original source file's SHA-256 may be registered. One declared format is used; multiple sources are not automatically merged.

| Format | Required columns | Label purpose |
| --- | --- | --- |
| `sleep_stages_tsv` | `onset_s`, `duration_s`, `stage` | Sleep stages and coverage |
| `bids_events_tsv` | `onset`, `duration`, `event_name` | Task events; may also retain `event_value` |
| `clinical_events_tsv` | `onset_s`, `duration_s`, `label`, `label_type` | Clinical events and source category |

`bids_events_tsv` is the current adapter name. It does not imply acceptance of arbitrary BIDS event tables or complete BIDS validation. An independent performance-evaluation interface for quality labels is not implemented.

## 3 Processing and methods

### 3.1 Explicit mapping and file checks — available

Embedded-annotation mapping requires selection of original labels, their interpretation and explicit confirmation. Absent labels, events beyond the recording and technical discontinuities cannot become task, sleep or clinical events. Sleep stages require positive duration and cannot be inferred from point events. Mapping retains original descriptions and source fingerprints in a new input revision without changing old records.

Registered fingerprints and required columns are checked. Onset must be finite and non-negative. Duration must be finite and non-negative, and sleep-stage duration must be strictly positive. If a sleep table supplies `end_s`, its difference from onset plus duration must not exceed `1e-6 s`.

Invalid time rows are reported and not mapped. Out-of-order rows and valid time rows beyond the registered recording length are reported but not universally discarded: counts are retained, and intersections with the selection are still mapped. Fingerprint mismatches or missing required columns fail the read.

### 3.2 Original time and sample mapping — available

Interval events are clipped to their intersection with the selection while retaining original, unclipped onset, duration and end. Zero-duration point events use a half-open rule: `selection start <= event onset < selection stop`.

Samples are mapped as `selection original starting sample + round((selected event time − selection start in seconds) × fs)`. An interval's `stop_sample` is exclusive. Point events have equal starting and stopping samples and contribute no duration.

### 3.3 Stage coverage and clinical-event duration — available

Sleep-stage coverage is the union length of overlapping intervals. Uncovered portions of the selection are explicitly `unknown`. Overlapping sleep stages are reported as an issue; conflicting stages cannot both be interpreted as confirmed state.

Clinical-event duration also uses interval unions to avoid counting the same time twice. Task events provide a list and positions only. Gaps between events do not mean “artifact-free,” and no task coverage or success rate is generated.

### 3.4 Separation of labels and signal detection — available

Sleep, task and seizure labels are excluded from M03–M06 and do not alter candidate thresholds or the total score. Alignment uses the provider's declared original clock; it does not measure hardware synchronization error.

## 4 Outputs and interpretation

The evidence file is `M07_annotations.json`. Counts refer to explicitly defined rows or intervals, not quality scores.

| Field | Unit or type | Meaning and interpretation |
| --- | --- | --- |
| `total_rows`, `valid_rows` | Row counts | All table rows and rows passing time parsing; the latter may still have out-of-range issues |
| `selected_count`, `events` | Event-row count, list | Source events intersecting the selection, with original and clipped coordinates |
| `stage_seconds` | s | Per-stage row sums; overlaps may be counted twice, so inspect `issues` first |
| `covered_seconds` | s or null | Sleep tables only: union length of stage intervals within the selection |
| `uncovered_intervals` | Intervals in seconds | Unknown sleep coverage; task and clinical events do not imply normal gaps |
| `clinical_event_seconds` | s or null | Clinical tables only: union length of event intervals in the selection |
| `sources`, `source_unchanged` | Fingerprints, boolean | Annotation identity and consistency during reading, not proof of label correctness |
| `issues`, `status` | Issue list, status | Issues or sleep-coverage gaps produce `partial`; event counts alone are insufficient |
| `quality_ground_truth`, `used_for_signal_detection` | Both false | Current labels are neither quality ground truth nor signal-detector inputs |
| `unlabelled_means_normal` | false | Unlabelled does not mean normal |

## 5 Configuration

| Setting | Current rule | Meaning |
| --- | --- | --- |
| `annotation.format` | One of the three declared formats | Current interface capability; no automatic guessing |
| `annotation.expected_sha256` | Must match when supplied | Annotation identity check |
| `annotation.source_path`, `source_expected_sha256` | May retain original labels and expected fingerprint | Conversion provenance |
| `annotation.label_scope` | Declares label purpose; absent means unconfirmed, non-quality use | A textual declaration is not converted to quality ground truth |
| Time-consistency tolerance | `1e-6 s`, for sleep endpoints and recording-end checks | Numerical tolerance, not synchronization accuracy |
| Assessment range | From M02; at most 120 s per window, with whole-record mapping per chunk | Short tails, gaps and unexecuted windows remain distinct |
| Embedded-annotation mapping | At most 512 original labels; interpretations up to 500 characters; note up to 2000 | Explicit confirmation creates a new revision, not automatic semantic inference |

There are no quality-deduction thresholds based on sleep stage, seizure duration or event count. Editing labels does not generate a new physiological diagnosis in this module.

## 6 Validation and limitations

Boundary checks cover point events, interval clipping, selection offsets, staging gaps, non-finite times and fingerprint mismatches. Actual mapping evidence exists for public sleep, task and clinical-event tables. This validates coordinates and interface behavior, not source-label accuracy.

Reader-extracted annotations are registered only after explicit user mapping and confirmation. The module does not infer semantics automatically, perform general BIDS validation, correct external clock drift or adjudicate annotator disagreements. Clinical labels may identify genuine pathological signals and must not be treated as technical artifacts for deletion.

Out-of-range annotations may remain in the selected-event list after an issue is recorded. Reviewers must consider `issues`, source files and recording length. Full annotation-management requirements in the specification do not imply that all capabilities are implemented.
