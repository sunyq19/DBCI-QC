# M02 Data characterization and check plan

Module guide · Applicable implementation: Workbench 1.0.0rc2 · Document version: 0.4

This module makes the recording, channels, time range and methods of a check explicit and reproducible. Technical facts determine applicability; context supports interpretation. Unknown information is not silently converted into established facts.

[Related specification](/en/standards#52-m02-data-characterization-and-check-plan) · [Prerequisite: M01](/en/standards/modules/M01)

## 1 Purpose and scope

M02 is a mandatory step for scalp EEG selection checks and method applicability. It organizes roles, acquisition-reference comparison groups, time windows, tags and method configuration. It neither computes an overall quality score nor changes detection thresholds from context tags.

Window and whole-record scopes are supported. Window scope assesses only the selected interval. Whole-record scope divides native continuous segments into chunks, executes each chunk and aggregates actual coverage. Execution coverage is not a quality acceptance rate.

## 2 Inputs and prerequisites

M02 depends on M01. Format-independent technical information is read first. The user then confirms modality, EEG and auxiliary channels, reference and context before QC recommendations are generated. Inputs also include the within-file start, duration, selected modules and parameters.

No scalp EEG recommendation is generated for an unconfirmed modality. Extracted information for sEEG, ECoG or MEG may be retained without running mismatched scalp methods.

`selection.reference_indices` assigns one original channel index to each ECG/EOG/EMG auxiliary role; it does not describe acquisition reference electrodes. `method_config.comparison_groups` assigns each selected EEG channel to an explicitly justified reference/comparability group. These two concepts are not interchangeable.

## 3 Processing and methods

### 3.1 Separate technical facts and context (available)

Sampling rate, channel count, units and auxiliary roles come from technical headers and actual selection. Disease, age-group and task tags retain their provenance. Missing or unconfirmed information remains unknown. Filenames, waveform appearance or a shared dataset name do not establish diagnosis or reference.

Unknown acquisition reference still permits some descriptive checks; methods needing comparable reference groups remain limited or unavailable.

Registered modality, channel roles, reference, context, processing history and annotation mappings can be corrected. Corrections create a new input revision with its parent and change record. Old jobs retain their frozen inputs; stale revision submissions are rejected. Processing history is a user declaration, not independent measurement.

### 3.2 Check selection and clocks (available)

The window must lie within recording and continuous-segment boundaries, meet resource limits, and use EEG and auxiliary signals at the same native sampling rate. Selection seconds are relative to the file's first sample; mappings preserve the source sample origin and time offset, including a nonzero FIF origin.

Whole-record chunks do not cross continuous-segment boundaries. Short tails and source gaps remain explicit. Per-window estimation, filtering and edge guards may produce different results; cross-window candidates are not automatically merged.

There is no automatic resampling, re-referencing or alignment of different clocks. Only voltage calibration is standardized to V. Each method filters its own copy when needed; there is no hidden shared filter applied before all checks.

### 3.3 Resolve dependencies and applicability (available)

M01, M02, M08 and M09 are mandatory. M03–M07 follow selection. Selecting M06 automatically adds M03 for integrity protection intervals. M05 depends only on M02 and computes its own channel indicators without M04's spectral results.

Optional extensions add their parent module. Recommendation, configuration adoption, plan preview and execution remain distinct. A ready plan does not mean computation has occurred. Changing input, selection or method settings requires the updated plan.

## 4 Outputs and interpretation

The plan and `M02_selection.json` preserve configuration and actual selection. Historical reports must not acquire tags from later edits.

| Output | Content | Interpretation |
| --- | --- | --- |
| `qc_config` | Channels, time window, context and method settings | Configuration actually used, not another run's defaults |
| `selected_modules`, `auto_added_modules` | Execution set and added dependencies | Distinguish not selected from unavailable conditions |
| `nodes`, `edges` | Planned states, reasons and dependencies | Planning information, not detection results |
| `data_tags` | Technical/context values, provenance and known/unknown status | Unknown does not mean normal or absent |
| `method_applicability` | Per-method availability and reasons | Retains limitations, non-selection and unimplemented methods |
| `recording` | Channel count, Hz, source origin and actual duration in s | Denominator of report coverage |
| `windows`, `coverage_plan` | Window coordinates and planned coverage | Distinct from executed coverage; source gaps are not normal data |
| `record_revision`, `parent_input_id` | Input revision and parent record | Historical job configurations are not overwritten |
| `raw_signal_mutation`, `quality_labels_used_for_detection` | Both `false` | Original signals are preserved; quality labels do not enter detectors |

Plan `ready` means conditions are met; `partial` means only some capabilities apply; `skipped` means omitted or not executable, interpreted with its reason. These are not signal pass/fail grades.

## 5 Configuration

| Setting or constraint | Current implementation | Basis and nature |
| --- | --- | --- |
| `scope` | `window` or `recording` | Selected window or whole-record chunking |
| Per-window duration | Greater than 0 and at most 120 s | Applies to every recording chunk, not the total recording length |
| `recording_options.window_seconds` | Default 120 s; also limited by memory budget | Chunks on the native sample grid, at most 10000 windows |
| `recording_options.expensive_methods` | Default `skip`; explicit `run` is available | Currently skips repeated per-window autoreject global-threshold cross-validation by default |
| Start | Nonnegative; window within bounds | Recording-time coordinate |
| Native rate | Same for selected EEG and auxiliary channels | Clock-adaptation constraint; no automatic resampling |
| Selection memory budget | `(EEG count + auxiliary count) × round(duration × fs) × 8` at most 256 MiB | float64 signal-array budget |
| Context | Missing values remain `unknown` | Known tags require provenance; no default disease or age |
| Comparison groups | Explicit per EEG channel; unknown is not filled in | Method applicability; details in M05 |

These are implementation settings and limits, not universal clinical duration, sampling or channel-count requirements. Disease, age and task do not currently change thresholds and do not constitute industry quality criteria. Language changes only presentation, not original channel names, stable IDs, numbers, units or configuration.

## 6 Validation and limitations

Engineering checks cover dependency closure, non-execution of unselected modules, rejection of excessive windows, non-overlapping roles, rate consistency and plan invalidation after edits. They support planning/execution consistency, not clinical validity of the recommendation policy. Real public recordings also have multi-window execution evidence; per-window coverage, cancellation and failure remain separate. Windows are not independent participants or experimental trials.

Missing reference, coordinates, filter history or auxiliary channels retains a specific limitation. Recommendations select available checks; they do not replace study design, clinical judgment or channel confirmation.
