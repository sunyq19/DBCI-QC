# M09 Reporting and human review

Module guide · Applicable implementation: Workbench 1.0.0rc1 · Document version: 0.4

This module provides local reports, a locatable candidate list and bounded raw-waveform previews. Human review is appended separately by version without changing algorithm results, original signals or the total quality score. It does not provide clinical diagnosis.

[Related specification: 5.9](/en/standards#59-m09-reporting-and-review) · [Prerequisite: M08](/en/standards/modules/M08) · [Source verification: M01](/en/standards/modules/M01)

## 1 Purpose and scope

The module applies to local tasks with results or explicit failure/unassessed reasons. M09 is mandatory and lets users inspect supporting evidence, open method results, and distinguish calculations from human confirmation.

Reports describe only the range actually assessed. A window report does not cover the entire recording. Whole-record reports distinguish executed, partially assessed, failed and unexecuted windows and source gaps. Coverage is not a quality acceptance rate.

This page describes current capabilities, not complete conformance with every reporting and review requirement in the specification. Unreviewed algorithmic candidates remain pending review.

## 2 Inputs and prerequisites

M09 depends on M08 summaries and uses saved source fingerprints, frozen configuration, run scope, actual module results and available evidence files. Waveform plotting also requires successfully loaded, calibrated raw data from the selection.

Channel identities, time and settings come from the saved task, not a draft changed later. Unrun modules and failed methods report their actual states without invented measures.

Without plottable signals, failure and unassessed reasons can be retained but waveforms must not be fabricated. Opening a report or successfully generating files does not establish valid signal detection or acceptable data quality.

## 3 Processing and methods

### 3.1 HTML and structured evidence — available

The report displays selected-channel count, sampling rate, original time range, module states and summaries, with access to corresponding JSON evidence. Source fingerprints, configuration identifiers, channel selection and actual parameters are retained in task results and structured output.

Readable module summaries do not replace detailed evidence. Mains-hit windows, for example, are not independent artifact segments; whole-selection channel candidates do not provide precise time localization; auxiliary events do not by themselves establish EEG contamination.

### 3.2 Static waveform preview in the report — available

The preview displays at most the first 6 selected EEG channels and the first 15 s of the selection, or the available range if shorter. The horizontal axis uses original-recording seconds; voltages are converted from V to µV.

Plotting uses a display stride of `max(1, N // 3000)`, where N is the native-sample count in the plotted time range. This selects display points only and does not alter analysis inputs. It does not guarantee that every brief spike will be visible.

`waveform_selection.json` retains channel names, start, actual displayed duration, display stride and units. This static plot does not change with workbench review actions and does not replace native-sample review.

### 3.3 Raw waveforms and candidate localization — available

The workbench rereads calibrated raw values from the frozen task input, checking source fingerprints. Requests are limited to 10 s, 16 channels, 2000 display points per channel and a 64 MiB native array. A read must stay within one native sampling stream and continuous segment. Gaps, invalid channels and changed sources are rejected, without automatic resampling or joining across discontinuities.

When the display budget is exceeded, a bucketed minimum/maximum envelope preserves extrema in temporal order and retains non-finite markers. Outputs include source samples, actual seconds, physical units and display scaling. Voltages display in µV; other physical quantities are not relabeled as voltage. The envelope is not every native sample and does not change analysis signals.

Candidates distinguish detected intervals from whole-window channel or channel-pair results. Whole-window results show their analysis range with an explicit absence of precise abnormal onset/offset. Physiological events and clinical labels are not promoted to quality candidates. Whole-record candidates retain window identity and original times; partial artifacts from unfinished windows are not promoted to final candidates.

### 3.4 Retain failed and unassessed results — available

If plotting fails, structured results remain available and M09 is marked `partial` with a reason. When signal loading fails, no waveform is fabricated; only acquired failure or unassessed evidence is reported.

Some modules may complete only a subset of methods. Reports retain component states, reasons and actual evidence. A single “report generated” status does not conceal downstream limitations.

### 3.5 Separate versioned review — available

After validating the candidate identifier, the workbench appends an `accepted`, `rejected` or `uncertain` decision, note, declared reviewer and timestamp to `reviews.json`. Each submission carries `expected_version`; stale versions conflict. Previous opinions remain in history, and the latest opinion forms the current review view.

Algorithm `result.json`, frozen requests and method artifacts are not rewritten. Initial `review_status=pending` in a static report is not current review progress. Current run summaries identify separate storage with `human_review_writeback=separate_versioned_review_store`; old reports retain their original fields. Decisions do not generate diagnoses, automatically alter signals or replace a null score with a percentage. Reviewer identity is user-entered, not an authenticated electronic signature.

## 4 Outputs and interpretation

| File or field | Unit or type | Content and interpretation |
| --- | --- | --- |
| `report.html` | HTML | Run scope, states, summaries and evidence access |
| `result.json` | JSON | Final task state, module results, settings and artifact list |
| `M08_assessment.json` | JSON | Aggregation evidence and uncalibrated total score; not a human conclusion |
| `waveform.png` | Image | Display-sampled waveform over limited channels and time; may be absent after plotting failure |
| `waveform_selection.json` | Names, s, sample stride, µV | Actual displayed range and display-processing description |
| `plan.json`, `environment.json` | JSON | Run plan, dependency environment and method-source information |
| Algorithm `review_status` | `pending` | Initial frozen-report state; current progress comes from separate review records |
| `human_review_writeback` | `separate_versioned_review_store` | Current runs identify separate versioned review without changing algorithm artifacts |
| `reviews.json` | `version`, `history` | Appended opinions and versions; the review API derives current decisions and counts |
| Raw-waveform interface | Source indices, seconds, samples, units and extrema envelope | Bounded original-value preview, not detector re-execution |

Plots, summaries and original method JSON contain different levels of detail. Before interpreting a candidate, check its channels, time, coverage and unassessed reasons rather than only summary counts.

## 5 Configuration

| Display setting | Current value or rule | Meaning |
| --- | --- | --- |
| Static-plot channels | First 6 selected EEG channels, at most 6 | Fixed preview scope, not a channel-screening conclusion |
| Static-plot duration | At most the first 15 s of the selection | Fixed preview scope, not the complete assessed duration |
| Display stride | `max(1, N // 3000)` native samples | Plotting only; no analysis decimation |
| Waveform units | µV; calculations use V | Display conversion |
| Raw-waveform request | At most 10 s, 16 channels, 2000 points per channel and 64 MiB native read | Display envelope only; no crossing continuous segments |
| Review state | `pending` / `accepted` / `rejected` / `uncertain` | Not a whole-record quality grade or clinical signature |
| Review fields | Reviewer up to 160 characters, note up to 4000; version must match | Append-only history with concurrent-overwrite protection |
| Total-score display | Uncalibrated | Uses M08 null; no score is generated by the report layer |

Static-plot settings are fixed. Raw-waveform requests can select channels, start and duration within the limits above; neither changes frozen analysis parameters. Check range and method settings must be confirmed in M02 and interpreted using values saved with the task.

## 6 Validation and limitations

Real public EDF tasks have generated local HTML, structured evidence and waveforms. Checks cover channel identities, original time, units, unassessed states and report access. They support reporting behavior, not expert review or clinical validity.

M09 does not write to original data. Whether an external action changed an input file during execution is determined by M08 source consistency, not merely by a report statement that raw data were preserved.

Candidate normalization, source channel/time mapping, extrema envelopes, version conflicts and preservation of algorithm files have independent engineering checks and actual public-recording HTTP workflow evidence. Static-plot sampling may still omit rapid changes. Bounded envelopes preserve bucket extrema but are not a diagnostic full-sample viewer or a universal cross-task quality comparison.

The specification requires traceable reports and human edits. The implementation covers automatic reporting and separate candidate-review history, not authenticated clinical sign-off. A quality report does not replace clinical diagnosis or acquire diagnostic validity from case or source labels.
