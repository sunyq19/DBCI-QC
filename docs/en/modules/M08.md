# M08 Evidence summary and comparability

Module guide · Applicable implementation: Workbench 1.0.0rc1 · Document version: 0.4

This module summarizes actual component results, reasons for unassessed items and source consistency. The total score is uncalibrated and remains null. Candidate counts, execution progress and missing items are not converted into a data-quality score.

[Related specification: 5.8](/en/standards#58-m08-evidence-summary-and-aggregation) · [Check plan: M02](/en/standards/modules/M02) · [Report: M09](/en/standards/modules/M09)

## 1 Purpose and scope

The module applies to selected methods and their actual execution evidence within the current window. M08 is mandatory and brings observations from different checks into one report while preserving their definitions, units and limitations.

It is not an automatic quality grader and provides no universal acceptance grade across devices, states or methods. A single-window result does not establish that a full-night recording, entire file or dataset has been assessed. Whole-record mode separately aggregates execution coverage from actual window states; partial, unexecuted and source-gap regions are not quality passes.

## 2 Inputs and prerequisites

Dependencies follow the actual selected set. M08 summarizes selected preceding modules and necessary dependencies; it does not force every check to run. Unselected modules remain skipped.

Inputs include the frozen plan, method configuration, component summaries, actual extension states, error or unassessed reasons, and fingerprints of the main file and required companions saved by M01. Source labels are limited to independent annotation and result review.

Partially failed results may be retained, but failed outputs must not be replaced with zero or interpreted as no detected problem. Execution status and quality conclusions must be read separately.

## 3 Processing and methods

### 3.1 Preserve component results and states — available

Module identifiers, execution states, reasons and original summaries are collected. Whether an optional extension actually ran or was limited is determined by execution output; `ready` in a plan is not completion.

Unselected, inapplicable, failed and completed checks remain distinct. If an existing module is `partial` or `failed`, the M08 summary is `partial`, with specific reasons retained. One successful check cannot conceal another method's failure.

### 3.2 Recheck source-file consistency — available

SHA-256 fingerprints of the main file and required companions are checked again against the member manifest saved by M01. A changed file fails M08; affected results cannot be accepted as having unchanged sources.

If prior source fingerprints are absent, consistency remains unknown rather than passed. Matching manifests and fingerprints establish byte consistency for this input, not correctness of acquisition, labels or device declarations.

### 3.3 Separate component evidence from a total score — available

`score.value` is fixed at `null`, displayed as “Uncalibrated,” with a reason. There is no implementation of score direction, normalization, weights, missing-item credit or a universal acceptance threshold.

Channel candidates, time candidates, channel pairs and fixed analysis segments are different statistical objects and are not added directly. Methods may detect the same data or cover different frequencies, channels or times. Summed counts do not measure fault extent.

### 3.4 Comparability and unimplemented capabilities

Frozen selections, settings, data facts and method evidence are retained so users can assess comparability. Automatic cross-dataset comparability certification and a unified cross-method bad-duration calculation are not available.

Combining candidates requires separately defined and validated channel scope, time unions, method overlap and unassessed-region rules. The current summary does not provide these rules and does not derive quality weights from disease or task labels.

## 4 Outputs and interpretation

The main evidence file is `M08_assessment.json`. Final task status is also stored in `result.json`.

| Field or result | Unit or type | Meaning and interpretation |
| --- | --- | --- |
| `score.value` | null | No usable total-score calibration; neither zero nor full marks |
| `score.label`, `score.reason` | Text | Uncalibrated status and reason |
| `module_assessments` | Component list | Module states, reasons and summaries; original method units are retained |
| `source_unchanged` | true or null | Matches M01 fingerprints, or lacks comparison evidence; detected changes fail the module |
| `execution_status_is_not_quality` | true | Execution states must not be converted to quality conclusions |
| `missing_capabilities` | Text list | Explicitly unimplemented capabilities, not deductions from completed checks |
| `status`, `reason` | Status, explanation | Read module rows and final task results separately from method candidates |

Unimplemented capabilities include spatial bad-channel prediction, local AutoReject, ICA/ICLabel, general repeated-data-block detection. This list defines boundaries; it does not imply clinical validation of other available methods. Human candidate decisions are now appended separately; they do not change frozen M08 results or generate a total quality score.

The final task result is `failed` if M01, M02 or M08 fails. Failure or partial assessment in other modules gives `partial`. These are execution rules, not data-quality grades.

## 5 Configuration

| Setting or constraint | Current behavior | Meaning |
| --- | --- | --- |
| Module selection | M08 is mandatory and summarizes actual selections and dependencies | Workflow rule |
| Total-score configuration | No available numerical weights or grading thresholds; fixed null | Uncalibrated capability boundary |
| Component parameters | Use the frozen method configuration for this run | No threshold retuning during aggregation |
| Statistical objects | Preserve each method's units and localization | No automatic count or bad-duration merging |
| Source verification | Recheck SHA-256 for the main file and required companions | Member-manifest and file-consistency check |

Frontend progress counts actually selected steps and describes execution only; it is not an M08 quality score. Results produced with changed parameters or method versions should not be treated as the same evaluation configuration.

## 6 Validation and limitations

Contract checks cover module states, dependency selection, missing conditions, extension failures, source fingerprints and a null total score. Real public-recording reports retain component results and the uncalibrated score. This supports aggregation behavior, not score validity across settings.

There is no universal bad-channel-fraction acceptance threshold, cross-method bad duration, automatic quality grade or target-application utility score. Zero candidates from one method does not mean unrun methods passed. Unassessed regions are not counted as normal data.

A usable total score still requires a defined purpose, direction, weights, missing-item handling, critical-issue rules and independent calibration. Specification requirements do not mean these are already implemented and do not authorize replacing null with an arbitrary percentage.
