# 流水线分配与逐模块数据验收

更新：2026年10月29日。九个顶层模块已独立实现，具备网页外运行接口、五格式接入、整记录分块和版本化人工复核。当前阶段按[数据覆盖验收规范](data-validation.md)扩充代表性记录，运行结果见[运行验收](runtime-validation.md)。真实运行、标签适配、准确性验证分别登记。

## 调度分为三层

1. **固定入口**：读取数据，核对来源、格式、标定、通道、时钟及配套文件，建立记录描述。通道表和文件不一致时先建立可追溯映射，不按标签名字直接合并。
2. **条件检查图**：依照每个方法的真实前提决定运行、未评或阻断；显式记录依赖顺序。疾病背景用于解释、保护和验证分层，不自动充当阈值。
3. **固定出口**：汇总可评范围、指标、候选和证据；保存报告与人工复核。算法失败、条件不足、无异常三种结果分别显示。

```text
M01 接入核验 → M02 数据画像和冻结计划
                         ↓
             M03 完整性 ─→ M06 生理伪迹线索
             M04 频谱干扰 ─────────┤
             M05 坏道候选 ─────────┤
             M07 状态和事件 ────────┤
                                   ↓
                        M08 分项与可比性
                                   ↓
                        M09 报告和人工复核
```

首版M05内部自行计算特征，不依赖M04。M06使用M03候选作为保护区；M08汇总所有选中模块。未来方法的具体依赖按声明更新。重新分析产生新的运行记录，每个子方法单独判断前提。

## 长记录如何执行

每个方法声明它需要局部窗口、整段背景还是整份记录的统计。读取可以分块，算法结论是否能合并则单独定义。工频多重比较的范围、坏道的相对统计、肌电包络标准化都会随分析范围变化；不能把多个独立片段的结果拼起来就声称等价于整记录分析，也不直接平均片段分数。

当前已按原生连续段和样本时钟分块，每窗最多120秒，保留短尾窗及失败、未执行和来源缺口。逐窗结果仍采用局部统计，尚不合并候选或声称等价于全局建模。长记录验收应同时记录运行时间与产物体积，为后续共享计算和证据存储优化提供依据。

## 验收级别与停止条件

每个子方法至少绑定一份可重复运行的输入和可核对的预期行为。上线清单分别保存：

- **工程已跑**：保存输入指纹、选道、范围、参数、真实结果和错误；不以能导入函数代替。
- **已知故障验证**：保存注入参数及位置，不改原始文件，不当成自然伪迹表现。
- **独立真实标签验证**：描述标签来源与口径，按受试者隔离开发和评估，报告误报和漏检。
- **目标场景复核**：检查设备、疾病/状态、参考和目标任务是否在已验证范围内。

缺少适用数据的模块留在设计目录；运行失败的模块标记失败；只有工程验证的算法可以作明确标识的研究预览，不能标为准确性已验证。不把来源提供的good/bad标签当成无需核查的专家共识。

## 当前扩展顺序

先重跑原有11份登记记录，再增加独立来源受试者、深睡、临床发作及真实SET，并单独验收长记录。新增记录与源标签使用固定版本和指纹；具体范围以[公开示例](public-examples.md)、覆盖矩阵和实际验收结果为准。

覆盖集稳定后再决定公共计算复用、模块层级和场景路由。自然标签的导联/时间映射、专家复核及受试者隔离评价先于阈值校准；不依据文件数量宣称通用评分标准成立。

数据来源：[EEGMMIDB](https://physionet.org/content/eegmmidb/1.0.0/)、[HMC](https://physionet.org/content/hmc-sleep-staging/1.1/)、[ds002034 v1.0.3](https://openneuro.org/datasets/ds002034/versions/1.0.3)、[TUAR](https://isip.piconepress.com/projects/nedc/data/tuh_eeg/tuh_eeg_artifact/v3.0.1/AAREADME.txt)。
