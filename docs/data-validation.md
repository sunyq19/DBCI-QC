# 代表性数据与报告验收规范

版本：1.0；状态：项目工程验收规范；适用范围：当前已接入的头皮 EEG 读取、推荐、模块执行和报告。检测准确性须按独立评价协议另行验证。

## 1. 验收单元

一个案例由原始记录、来源说明、明确的选道与分析范围、配置、预期行为和运行证据组成。同一受试者的不同记录、同一记录的不同窗口、跨格式副本应保留关联，不得计作独立受试者。

每个案例应保存：

| 字段 | 要求 |
| --- | --- |
| 身份 | 案例 ID、数据集及版本、来源受试者 ID（如可核实） |
| 来源 | 官方 URL、许可、原始文件及配套文件 SHA256 |
| 信号 | 实际格式、源通道索引、通道角色、单位、采样率、原始时钟和时长 |
| 配置 | 模态、选道、参考、分析范围、方法参数及其来源 |
| 背景 | 已核实的任务、疾病或状态；未知和来源冲突应明确记录 |
| 标注 | 标注类型、计数单位、时间范围、导联构型、标注依据与局限 |

未提供的参考、坐标和预处理信息不得以经验值代填。来源说明互相冲突时应保留冲突及原件，相关字段维持未核实状态。

## 2. 执行与证据

默认验收应采用工作台的确定性推荐方案，并冻结推荐结果、实际计划及参数。需要全部基础模块对照时应明确选择 `all-base`，不得与默认推荐结果混为同一配置。可选算法仅按配置或推荐启用。

每个案例应满足：

1. 运行前后原始信号及登记标注指纹一致；已登记指纹不一致时拒绝重新确立基线。
2. 选中模块、依赖、实际执行状态和报告计划标识一致。
3. 每项部分可评、跳过和失败状态均有原因；缺少信号或适用条件不得作为质量合格。
4. 实际分析的通道、时间和单位可追溯，结果与 HTML 报告均落盘。
5. 整记录检查应分别报告已执行、失败、未执行和来源缺口，并核对覆盖量守恒；任一窗口失败不得以总体 `partial` 隐藏。
6. 未经校准的总质量分保持 `null`。

源记录总时长与本次分析时长应分列。短窗验收不代表完成整记录检查；分块检查不等同于整段一次估计，且窗口数量不等于独立样本数量。

## 3. 验收结论

| 结论 | 含义 |
| --- | --- |
| `passed` | 请求范围内执行完成，来源不变，必要报告及证据完整 |
| `failed` | 执行、指纹或证据检查失败，保留错误和已产生的结果 |
| `budget_skipped` | 超出明确设置的处理范围预算，未执行，不计通过 |
| `timed_out` | 达到单案例运行时限，保留已产生结果，不计通过 |

`completed`、`partial`、`skipped` 是方法执行/适用状态；`passed` 是工程验收结论。两者均不表示数据质量优良或检测准确性已通过。人工复核另存意见，不改写自动结果。

## 4. 科学评价边界

睡眠分期、任务提示、疾病分组和临床发作区间应作为解释背景，不得充当伪迹真值。来源记录级坏道标签与短窗口候选只可进行描述性比较；评价检出率前应核实异常时段、标签协议和标注一致性。

时间区间、通道、通道对和固定窗口属于不同计数单位，不得直接相加。双极导联标签与单电极信号应先核对导联及时间映射；未对齐时不得计算通道级准确率。未标注区间不自动视为干净区间。

独立评价应在调参前固定受试者划分、标签映射、计数规则和评价指标，保留阳性、阴性及分歧案例。合成注入仅验证指定故障的响应，不替代自然伪迹验证。本规范未定义疾病专属阈值或统一质量总分。

## 5. 复现入口

使用具有计算依赖的 Python 环境。登记文件接受 `inputs`、`records` 或记录数组；路径相对登记文件解析。输出目录必须是仓库外的新目录。

```bash
python scripts/validate_data_coverage.py \
  --config /path/to/records.json \
  --output-dir /path/to/new-coverage \
  --max-total-seconds 3600

python scripts/validate_data_coverage.py \
  --config /path/to/records.json --record-id example \
  --scope recording --max-record-seconds 20000 \
  --max-total-seconds 20000 --timeout-seconds 1800 \
  --output-dir /path/to/new-whole-record-coverage
```

`--max-total-seconds` 和 `--max-record-seconds` 限制拟处理的源信号秒数，`--timeout-seconds` 限制单案例运行时长。批次默认上限为 32 个案例。发生失败后继续其余案例；任何失败、超时或预算跳过均使批次返回非零退出码。

输出 `index.html` 提供逐案例报告入口，`coverage.json` 保存机器可读覆盖矩阵。每个案例独立保存输入声明、新读取的技术元数据、推荐、配置核对、实际计划、事件日志、验收结果、输入前后指纹及 `job/` 内的完整报告。

新增数据应先建立冻结案例，再用于模块重构的结果比较。共享计算、层级和路由的调整应继续通过已有案例；发生预期变化时须注明原因，不得只更新参考结果来消除差异。
