[头皮 EEG 规范](/standards) · [检查规则](/standards/eeg-checks) · [评分规则](/standards/eeg-scoring) · [来源与依据](/standards/eeg-evidence) · [返回质控台](/)

## 1 范围与报告原则

本文件规定人类连续头皮 EEG 基础技术质控报告的内容与追溯要求。报告应描述本次实际执行的检查，不代替临床诊断、数据用途审批或外部标准认证。

报告正文宜简洁，详细方法、参数与证据可展开或链接。以下六部分应能定位：记录概览、覆盖与适用性、分项证据、候选与波形、方法与来源、人工复核与限制。

当前 EEG 选区与整份记录报告默认按“评分概览 → 结果总表 → 重点复核 → 检查明细 → 评分依据”组织，后两项中的具体内容可展开。缺少可选条件只影响对应检查，不将整份报告标为受限；执行失败仍明确展示。

“必填”要求信息项或其缺失状态被明确记录，不要求制造非空值。“条件必填”表示执行相关方法或出现相关结果时必须记录。没有运行、运行失败、条件不足和完成后零候选应分别表达。

## 2 记录概览

### 2.1 必填内容

| 信息项 | 要求 | 当前结构化位置 |
| --- | --- | --- |
| 记录与任务身份 | 区分输入记录、版本与本次运行；保留可追溯的计划标识 | `artifacts/plan.json` 的 `plan_id`、`input_lineage`；任务目录及冻结请求 |
| 来源与文件 | 主文件及必要伴随文件、格式、SHA-256；来源版本和原始/派生状态未知时明确说明 | `result.json` 的 `source_sha256`、`source_files`、`input_provenance`、`input_data_usage`、`input_lineage`；`artifacts/M01_input.json` |
| 信号对象与模态 | 记录所选信号对象与模态来源；格式不证明模态 | `result.json` 的 `input_modality`、`input_metadata`，NWB 另有 `source_signal` |
| 物种与专项范围 | 说明是否有来源支持人类头皮 EEG 范围；未知不默认为人类 | `eeg_assessment.population_confirmation` 记录运行接口尚未采集完整范围确认；完整语义见字段字典 |
| 通道与采样 | 分开报告存储通道、选中通道及方法有效通道；采样率 Hz、实际样本数、单位与标定依据 | `artifacts/M01_input.json` 的 `streams`；`artifacts/M02_selection.json` 的 `recording`、`channels`；方法产物 |
| 时间与连续性 | 原生时钟、实际起止、所选流与连续段；输入时长和分析时长分开 | `result.json` 的 `recording`、`qc_config.selection`；M01 的 `clock`、`streams`；M02 的 `selection`、`recording` |
| 参考与处理背景 | 已知采集/当前参考、比较组、滤波与派生史；来源不足时说明限制 | 冻结的 `input_metadata`、`qc_config`；M02 的 `comparison_groups`、`processing_applied`；来源资料 |

`processing_applied=[]` 只描述本次读取阶段没有附加处理，不证明源文件从未滤波、重参考或清洗。`reference_channels` 保存 ECG/EOG/EMG 辅助角色，不等于 EEG 的采集参考电极。

### 2.2 背景信息

来源提供年龄、疾病、药物、清醒/睡眠或任务信息时，应保留原值、来源及作用范围；未知应保留未知。年龄应包括单位、起算依据和时间语境，时段状态不应被整份文件标签替代。

[字段字典](/standards/fields)定义完整语义；当前运行接口仍有 `disease`、`age_group`、`task` 等既有上下文字段，未整体实现新字典的来源与确认结构。既有标签不能证明已完成物种、年龄或临床背景核验。缺失背景不自动阻止可可靠执行的技术测量，但应限制相关解释。

## 3 覆盖与适用性

### 3.1 必填内容

报告应同时说明输入范围、请求范围、实际分析范围和展示范围。至少包括：

- 选区或整记录模式，所选流、原始通道身份、起止样本、实际秒数及采样率。
- 实际执行的检查、依赖条件、有效频带及有效通道/时间范围。
- 未选择、条件不足、失败、部分可评项目及具体原因。
- 来源缺口、未覆盖尾段或窗口、无效样本等影响解释的范围。

选区证据见 `artifacts/M02_selection.json`、`result.json.modules` 和各方法产物；整记录证据见 `artifacts/coverage.json`、`artifacts/window-results.json` 与各窗结果。

### 3.2 覆盖的解释

整记录覆盖量应使用自身声明的分母，并区分来源可用样本、缺口、执行完成、部分可评、失败和未执行范围。完成窗口也可能包含方法级未评项，不能据窗口状态声称所有检查覆盖了全部样本。

覆盖率是执行范围描述，不是数据合格率。没有经过验证的跨方法、跨窗去重规则时，不应报告“全部伪迹占比”或统一坏时长；原始候选、窗口及重叠关系应保留。

## 4 分项证据

### 4.1 每项检查的必填结构

| 内容 | 要求 |
| --- | --- |
| 稳定身份 | 检查 ID、标题、规则目录版本及映射模块 |
| 适用性 | 所需条件是否可核对，限制和缺项动作 |
| 执行 | 实际模块与方法状态；不得把计划中的可运行状态当成执行完成 |
| 测量 | 原始数值、单位、计算范围、窗口、有效分母及参数 |
| 判据 | 阈值数值或计算方法、性质、来源、是否实际启用 |
| 证据 | 方法产物、其中字段或条目位置、原始通道与时间坐标 |
| 解释边界 | 观察量、候选或复核结论的层级，尚未验证的用途 |

检查目录与模块执行状态的对应不构成逐项合格判定。一个模块内不同方法可能分别完成、受限或失败，应继续读取各方法的状态及证据。

### 4.2 词条与证据文件

下表路径相对于任务的 `artifacts/` 目录。文件只在相关步骤实际生成时存在；缺少文件应结合状态说明原因，不生成空证据冒充已完成。

| 检查 | 模块 | 主要方法产物 | 应呈现的核心内容 |
| --- | --- | --- | --- |
| EEG-001 文件、来源与结构 | M01 | `M01_input.json` | 来源成员指纹、读取器、数据流、标定与结构警告 |
| EEG-002 信息、参考与范围 | M02 | `M02_selection.json`、`plan.json` | 实际选区、通道身份、比较组、原生单位与冻结配置 |
| EEG-003 非有限值、恒值与端点 | M03 | `M03_continuity.json` | 候选类别、持续时间与容差、原始定位、端点可评条件 |
| EEG-004 Welch PSD | M04 | `M04_spectral.json` | 频率、功率密度、单位、窗函数及实际谱估计参数 |
| EEG-005 窄带工频线索 | M04 | `M04_spectral.json` 的 `line_noise` | 观测频带、窗口、比较统计、候选与未评状态 |
| EEG-006 谱模型与 alpha 描述 | M04 | `M04_spectral.json` 的 `parameterization` 及相关谱描述 | 拟合频带、模型与拟合状态；不将生理峰缺失判坏 |
| EEG-007 非空间坏道候选 | M05 | `M05_bad_channels.json` | 分组、有效通道、阈值启用、分项指标和通道候选理由 |
| EEG-008 辅助信号锁时线索 | M06 | `M06_auxiliary_events.json` | ECG/EOG 辅助状态、事件与锁时证据；缺导联或片段的原因 |
| EEG-009 高频活动线索 | M06 | `M06_muscle.json` | 有效频带、高频候选、EMG 支持状态及完整性保护 |
| EEG-010 标注与时间核对 | M07 | `M07_annotations.json` | 标注类型、时间映射、越界/覆盖、标签是否为质量真值 |
| EEG-011 分项证据与覆盖 | M08 | `M08_assessment.json`；整记录另有 `coverage.json` | 模块状态、未评原因、来源一致性、总分未校准 |
| EEG-012 报告、追溯与复核 | M09 | `report.html`、`waveform_selection.json`；任务根目录 `result.json`、`reviews.json` | 运行证据、展示范围、人工决定及独立版本 |

可选扩展另有 `Mxx_<extension_id>.json`，应记录实际后端和方法版本。Python 重实现、原版代码调用及 Octave 兼容运行应分别表述，不应统称为已验证等价。扩展的候选不改变基础检查词条的语义。

### 4.3 数值和状态

零候选仅表示在声明范围与规则下未产生候选。未计算、非有限值、没有有效分母或尚未建立的总分应为 null，并保留状态或原因。布尔未知不能写成 false，未提供标注不能写成确认无事件。

`completed`、`partial`、`skipped`、`failed` 是执行状态，不是质量等级。方法内部的 `computed`、`no_events`、缺条件等状态应保留，不由模块汇总状态覆盖。候选数量还应区分通道、通道对、事件、区间和固定窗。

## 5 候选与波形

### 项目试行基础评分

当前规则为 `project-weighted/1.0`；定义、公式、缺项处理、算例与验证要求统一见[EEG 评分规则](/standards/eeg-scoring)。报告应标注“项目自定义 v1.0”，同时列出分项权重与配置标识。

每通道分别计算非有限或恒值样本占比、工频命中窗占比、高频候选时长占比。每个分项等于 `100 × (1 − 通道异常占比的均方根)`，总分取三个分项的最低值。三项应完整覆盖所选通道；缺项不出总分，不重新分配权重。

分项应保留原始分子分母、均方根负担、均值、最大负担通道及有效通道数；原始总体未命中比例与新得分应分开记录。ADC 端点、组内异常、辅助锁时等其他检查另列，不声明已被基础分数覆盖。当前规则不设行业合格线或用途通过率。

评分保存在 `report_view.score`，与通用接口保留的 `score.value=null` 区分。新任务冻结当前评分；历史任务可从冻结证据生成新版视图，但必须显示重算版本与旧分数，原文件不改写。不同评分版本不直接排名。

### 候选展示

存在候选时，下列项目为条件必填：稳定候选标识、来源检查及方法、类别、理由、原始通道身份、定位粒度、证据引用和复核状态。可定位时间区间还应记录原始样本或秒坐标及端点约定。

仅有整窗或通道级结果时，应明确“未定位异常起止”。通道对候选应同时保留两端，不擅自确定其中一条为坏道。标注中的发作、任务事件或睡眠阶段不能直接升级为伪迹候选。

波形和频谱图应注明显示通道、时间、单位、增益或显示处理。当前静态波形最多展示前 6 个所选通道的最初 15 秒，参数记录在 `waveform_selection.json`；它不代表全部分析范围。原波形接口的极值包络是有界预览，不是全部原生样本或诊断级浏览器。图像不可用时，应保留说明及已有结构化证据，不生成替代性的示意数据。

## 6 方法、参数与来源

### 6.1 冻结配置与方法身份

应保存实际使用的参数，不只提供软件默认参数链接。`artifacts/plan.json` 保留计划，`result.json.qc_config` 保留运行配置，`artifacts/environment.json` 保留软件与依赖版本、实际方法源码指纹。可选扩展的参数和执行信息还应核对其独立产物。

来源依据应使用稳定标识，链接到[来源与依据](/standards/eeg-evidence)。报告应区分资料支持的方法定义、外部采集建议和本项目暂定判据，不将参考文献存在本身当作阈值已验证的证明。

### 6.2 项目规则快照

新 EEG 任务在 `result.json.eeg_assessment` 和 `artifacts/eeg-assessment.json` 保存本次规则映射；`artifacts/eeg-rules.json` 保存对应检查目录。其作用是追溯，不是自动符合性评价。

| 字段 | 含义 |
| --- | --- |
| `schema_version` | 快照结构版本 `eeg-assessment/1` |
| `catalog_version`、`specification_version` | 检查目录 `eeg-basic/1.1` 与规范 `0.8` |
| `catalog_sha256` | 对应规则目录的 SHA-256；规则变更可与本次报告区分 |
| `claim` | `project_rule_traceability_only`：仅声明项目规则追溯 |
| `conformance` | null：不生成合规分数、认证或逐项合格结论 |
| `population_confirmation` | `not_captured_by_runtime`：运行接口尚未采集完整人群范围确认 |
| `checks[]` | 各词条的 `id`、`title`、`module_id`、`module_status`、`module_reason`、`source_ids`、`parameters`、`measurement_summary` 与 `evidence` |
| `checks[].evidence[]` | 产物相对路径 `artifact`、文件 `sha256` 和可定位的 `fields`；应以实际产物核对 |
| `child_artifact_maps[]` | 仅整记录：每窗原始产物名到父任务导出名的显式对应；子快照中的相对文件名经此映射解析，保持原始 JSON 字节不变 |

模块状态映射不能证明一个模块内每个方法都完成，摘要不能替代详细方法证据。整记录应保留逐窗快照及其映射关系，不制造跨窗统一检测结论。旧报告不回填为已使用新规则。

## 7 人工复核与限制

### 7.1 复核记录

未复核的自动候选应标记待复核。发生人工复核时，应独立保存候选标识、接受/拒绝/不确定决定、理由、复核者声明、时间、版本和历史。当前 `reviews.json` 在任务根目录追加保存；最新进度应读取复核记录，不能只读取冻结报告中的初始 `review_status=pending`。

复核意见不覆盖 `result.json` 或方法产物，不自动删改数据，也不把 `score.value=null` 改成百分比。使用者填写的复核者名称不等于经过认证的电子签名。

### 7.2 必须说明的限制

报告应说明通用质量总分尚未校准；采用上述项目试行指数时标明版本，并保留实际存在的缺项、未评、失败和仅描述内容。没有独立专家标签验证时应如实说明；公开记录跑通与少量人工查看不构成检测准确率或跨疾病有效性证明。

当前规则快照提供检查定义到执行证据的映射；完整物种、年龄等字段尚未迁移至运行接口，独立专家验证尚未建立。报告不应声称已满足完整字段规范或已获得通用 EEG 质量合格判定。

## 8 报告保存与一致性核验

报告包应保留 `result.json`、可读报告、冻结计划、环境、规则快照和实际生成的方法证据；人工复核记录作为独立追加版本保存。只有整记录报告时，也应能够进入对应窗口证据。整记录导出的子窗文件以窗口 ID 和 `--` 前缀区分，不能将不同窗同名文件相互覆盖。

发布或交接前应核验：来源指纹和选区一致、单位与坐标一致、词条与实际方法对应、跳过/失败可见、图示范围准确、证据链接有效、null 未被替换为零、规则版本可追溯。该核验属于报告与工程一致性，不代替检测性能验证。

## PDF 与结果总表

EEG 选区及整份记录报告提供 PDF 下载，与页面使用同一份评分和检测证据。第一页为记录范围、三项得分、扣分与测量值；第二页为候选位置、对应原始波形和人工复核栏。导出不修改原始结果。

每项扣分为 100 减去该项得分。缺项标记未评，不按零扣分处理。候选图展示前两条高频候选；没有高频候选时展示工频候选。原始文件不能通过来源校验时省略波形并说明，保留已有检测结果。

安装 PDF 组件：`pip install -e ".[reports]"`。可通过 `DBCI_QC_PDF_FONT` 指定支持中文的 TrueType 字体；导出结果需确认中文显示正常。

## 整份记录汇总与后台执行

默认检查所选文件、所选信号流的全部时长。后台采用不重叠的原生连续段分块，保留原始采样时钟；网页关闭不终止任务，本机服务须持续运行。可选择快速预检，只检查选区。

整份评分采用 `project-weighted/1.0`：先累加各通道和各窗口的候选量与有效量，再计算各分项未命中比例，按冻结权重求平均。不得直接平均窗口分数；短尾窗采用真实分母。检测器阈值不因评分升级而改变。

总分必须有完整的执行与来源核验，并且每个窗口的三项测量齐备。失败、未执行、来源缺口或短尾窗不可评分时，保留分项和覆盖信息，整份总分为空。检查执行覆盖与方法内有效样本、有效时长应分开说明。

报告同时展示最低通道分项、通道分项表、逐窗分数及原始候选位置。整体分项使用通道异常占比的均方根，局部原值仍独立展示。100 分表示这些检查未产生扣分候选，不证明所有用途适用。

分块边界会影响滤波、稳健统计与候选；高频方法会剔除边缘。应固定分块配置进行比较。此功能覆盖一份记录，不等同多文件队列的群体质量分；批量同条件比较独立维护。
