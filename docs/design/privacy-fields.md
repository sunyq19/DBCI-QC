# 质控台敏感字段处理设计

设计草案 · 2026-11-05 · 待开发

第一版解决从文件读取到报告分享之间的字段流转。每份记录有一个展示编号，每个检查只接收计算所需的信息，分享报告按明确的字段清单生成。字段规则由项目维护。需要跨次关联时，使用数据提供方给出的研究编号，姓名与研究编号的对照表由提供方保管。

## 放在流程中的位置

读取入口负责处理文件名、路径、配套关系和原始头信息。M01/M02 建立来源引用及计算所需的字段。M03–M07 按实际方法取数，M08 汇总指标，M09 根据用途生成内部复核报告或分享摘要。隐私提示记录在数据接入与输出环节，独立于信号评分。

| 字段 | 读取和本地复核 | 算法与分享摘要 |
| --- | --- | --- |
| 记录编号 | 每份记录分配无身份含义的编号，重开同一记录时沿用 | 算法和报告用此编号关联结果。展示编号与可访问任务的链接分开 |
| 来源路径、文件名、ZIP 成员名 | 读取器用于打开文件、解析配套引用，原值限于受控工作区 | 普通日志使用编号和文件角色，分享摘要省略路径与文件名。相对路径也按此规则处理 |
| 姓名、住院号、文件头患者字段、自由备注 | 按格式检查已知字段，发现候选时只登记位置和类型 | 基础算法跳过这些字段。分享摘要和普通错误提示均省略原值 |
| 通道、标注、时间 | 保留原始索引、命名、事件及时间基准，以便院内复核 | 方法按需使用经核对的通道角色、事件码或时间信息。分享默认使用通道序号和记录内相对秒，原始标签和绝对日期留在内部 |
| 信号、技术参数及质控结果 | 在本地计算和查看波形、采样率、单位、分项与证据 | 分享可包含核验类型和范围后的数值、规则版本及固定术语。原始波形、任意字符串和附件留在内部 |

规则表记录字段来源、允许用途、输出转换和缺项处理，随实现做版本控制。新增字段默认限于内部，经审查后加入分享清单。同一记录编号只标识一次记录。医院提供的受试者研究编号用于院内跨记录核对，分享摘要默认只带记录编号。

## 输入与输出

1. **接收。** 用户点击读取前，在上传处说明将保存本地副本及清理方式。原始文件进入限制访问的工作目录，保留配套相对路径及原始文件内容。为记录持久保存一项独立的随机展示编号。预登记和历史记录首次需要展示编号时使用同一机制。重试确认沿用同一编号。
2. **检查。** 在已有读取器旁检查可取得的字段。第一版覆盖原文件名、ZIP 成员名、EDF/BDF 文件头患者栏和平台自由文本。后续接入 BIDS 数据包时再覆盖相应表格。逐项记录已查、需复核或未检查。遇到未知格式或读不到的字段时记录原因。
3. **传给算法。** 由调度器按方法提供波形、稳定通道身份、采样率、单位和必要标签。需要配套引用或原始标签的方法在受控范围内使用。第三方库产生的原始警告或异常可能带路径，普通任务日志和界面错误只接收预定义错误码、编号及处理建议。
4. **生成分享摘要。** 在服务端从测量结果逐项构造分享数据，供预览和 PDF 共用。报告标题、下载名及 PDF 文档属性使用展示编号。第一版仅导出摘要，详细证据、波形图、自由复核意见、内部链接和原始 JSON 留给内部复核。分享数据生成失败时给出固定提示。既有任务也按这份规则生成新摘要，原始报告另行保留。

本地提示示例为“记录 R023 的 EDF 患者栏需复核”。保存的提示只需规则、位置、状态。例如用固定字段名 `edf.patient` 或 ZIP 条目序号定位。字段用途或内容模式可以触发复核，患者栏有值也可能只是研究编号。保护分享输出主要依靠允许导出哪些字段，即使漏认一个姓名，原始自由文本也没有导出入口。分享授权由提供方确认。

## 首轮验收

- 用虚构标识分别构造带姓名的文件名、ZIP 子目录、EDF 患者栏、通道标签和复核备注。依次检查摘要预览、下载名、PDF 正文和属性、普通运行日志，要求测试标识和绝对路径出现次数均为零。
- 加入合法配套包和重复通道名。核对与原流程的通道对应、采样率、时段、分项测量和评分一致。展示编号变化只影响呈现。
- 触发一次含路径的底层读取错误，再对一个带敏感旧标签的历史任务生成分享摘要。核对失败提示、历史导出和日志执行相同规则，保留“未检查”的覆盖状态。
