# 质控平台顶层设计 v1.0

版本：platform-design/1.0。固定日期：2026-11-06。

本版固定后续开发的产品结构、数据关系和部署方向。平台以数据为中心，统一接入、检查计划和结果；计算可在云端或数据所在单位执行。首期优先完成 EEG，沿用现有独立模块扩展其他模态。

这是产品与系统架构基线，不是已审核的质量判定标准，也不表示以下目标已全部实现。具体阈值、评分公式和适用范围继续在质控标准文件中单独维护。

模块职责、数据路由及启用条件配套固定于[模块与启用规则 v1.0](module-routing-v1.md)，包含可直接用于展示的总图与条件表。

## 1 固定的设计决策

| 决策 | 本版约定 |
| --- | --- |
| 产品入口 | 统一“接入数据”，不要求用户先选择单文件质控或数据集质控 |
| 数据层级 | 数据集 → 个体 → 会话 → 记录；文件与信号流是记录的组成部分 |
| 检查内容 | 完整性与一致性检查、信号质量检查共同服务同一份数据；按前提启用 |
| 模态 | EEG、ECoG、sEEG、连续 AP/LFP 等决定方法适用范围，不各建独立工作台；Neuropixels 另保留采集技术属性 |
| 数据位置 | 支持上传到云端、关联已有云端数据、本地执行三种接入方式；不要求全部原始数据上云 |
| 计算组织 | 后台任务、按记录或受控时间窗执行、限制并发；网页负责操作与查看 |
| 结果组织 | 数据集总览可进入个体和记录详情，共享来源、任务与报告，不重复上传 |
| 核心交付 | 读取器、检查模块、计划和结果契约独立于网页；为 CLI、本地执行和未来 Linxi 适配复用 |
| 原件与历史 | 保留原件和历次结果；修正元数据、参数或数据后创建新版本和新任务 |

## 2 用户流程与页面

```text
接入数据：上传 / 已有云端数据 / 本地执行
                       ↓
读取文件，整理个体、会话、记录和配套资料
                       ↓
确认必要信息、检查范围和可比较分组
                       ↓
推荐检查方案，显示检查位置与范围
                       ↓
                  后台执行
                       ↓
数据集总览 → 个体详情 → 记录详情 → 问题证据
```

首页保留清晰的数据接入入口、检查框架和历史数据。完成读取后展示实际信息，仅要求补充会影响本次检查的必要字段。长说明、方法参数和来源按需展开。

| 页面 | 主要内容 | 进入方式 |
| --- | --- | --- |
| 数据集总览 | 应到/实到、个体与记录数、一致性问题、信号检查覆盖及问题记录列表 | 导入多记录数据包，或打开已有数据集 |
| 个体详情 | 会话与记录列表、配套资料对应关系、个体内冲突及每份记录结果 | 点击总览中的个体 |
| 记录详情 | 技术信息、适用模块、信号分项、通道/时段定位及证据 | 点击记录；仅提交一份记录时直接进入 |

只有一份记录时，系统仍保存统一的数据归属，但不强迫用户填写整套项目和个体信息。个体或会话未知时保留未知，不制造身份关系；单份记录不能证明跨记录一致性。

页面保留随当前对象变化的模块图：总览突出 D01–D03，记录详情突出 M01–M09，并提供直接返回上一级的位置。顶栏继续保留质控标准和语言切换；接入方式属于数据操作，不扩展成多套网站导航。

实施更新（2026-11-06）：`/` 已统一上传与已有数据目录，`/datasets?package=...` 为数据集详情；总览—个体—记录共享来源与运行历史。旧地址继续兼容。具体字段与汇总边界见[入口与汇总 v1](dataset-overview-v1.md)。

## 3 数据关系与版本

一份记录可以由多个文件组成，例如 BrainVision 的头文件、标记文件和二进制信号。一个 NWB 文件也可能包含多个独立信号流。文件数、记录数、流数分别统计，多流不自动拼接。

| 对象 | 必须表达的关系与事实 |
| --- | --- |
| 数据集 | 数据归属、来源与版本、交付范围、应有清单及其依据 |
| 个体与会话 | 已声明的编号、对应记录及确认状态；不同项目不因同名编号自动合并 |
| 记录与信号流 | 主文件、配套文件、原生通道与时钟、模态、处理史、父记录及技术字段来源 |
| 比较组 | 本次可比较的记录集合，以及通道、采样率、单位、参考等一致性要求 |
| 检查计划 | 输入快照、模块/方法版本、参数、已选范围、条件判断、规则和评分版本、计算位置 |
| 运行与结果 | 计划标识、执行端、来源指纹、实际覆盖、状态、指标、问题证据、报告与独立人工意见 |

在现有 DatasetCard、RecordingDescriptor、QCPlan、QCResult 的职责上补充关系与运行追溯，具体 API 字段通过后续版本化契约实现。本文件不直接改变现有接口。

应有清单与本次扫描结果分别保存。清单缺失时可检查已接收文件的结构与内容，但交付完整性保持未确认。原始与派生记录、不同植入期和不兼容采集配置分别分组；疾病名称相同不自动获得可比资格。

## 4 模块分工与路由

```text
统一读取器与来源核验
          ↓
     信息确认与计划
          ↓
   ┌──────┴────────────────┐
   │                       │
资料完整性与一致性       记录信号质量
D01 应有文件与结构      M03 信号完整性
D02 个体及跨文件对应    M04 频谱与干扰
D03 同组配置与重复线索  M05 通道质量
                       M06 伪迹线索
                       M07 事件与时间
   │                       │
   └──────┬────────────────┘
          ↓
  统一汇总、证据、复核与导出
```

保留 M01 读取与结构、M02 信息与计划、M08 汇总、M09 报告职责，保留 D01–D03 的独立接口。图示表达产品职责；具体执行依赖以冻结计划为准，不要求两条分支同时运行。

共同读取结果可在来源与版本匹配时复用。D02 检查跨文件的事件范围和对应关系；M07 检查当前分析记录的标注与时间，两者引用相同时间定义和证据，避免重复扣分。数据集报告通过聚合适配层组合 D 结果与 M 报告，不把多个记录强行塞入现有单记录 M08/M09 接口。

异常按依赖影响范围处理。缺少某个体的一张表，不阻止其他个体运行；单位不明只阻止依赖电压标定的分析。无法读取的记录保留失败原因，不从完整性分母中消失。信号检查按已确认的模态、信号对象、技术条件和所选方法执行。

## 5 数据接入与计算位置

| 方式 | 原始数据位置 | 执行方式 | 首期安排 |
| --- | --- | --- | --- |
| 网页上传 | 上传后进入私有 OSS | 云端执行器按记录取数、检查并保存结果 | 先支持受控规模的试用数据，分片与断点续传 |
| 关联已有云端数据 | 受授权的云端数据目录 | 关联固定对象版本，复用同一执行器，不重复上传 | 先用于预置公开样例，后扩展单位已有存储 |
| 本地执行 | 医院、实验室工作站或服务器可访问的目录 | 本地工具/Docker 实际检查，按允许范围回传结果 | 后续接入；初期可先导入本地结果包，再增加任务联动 |

云端网页不能读取用户电脑上的绝对路径。NAS 路径由能访问该 NAS 的执行端处理；用户在云端填写一个本地路径不会使数据可访问。

大型数据按文件清单接入，避免要求把全部数据打成一个巨型 ZIP。多文件格式保留配套关系；新快照仅传新增或变化的文件。计算时按记录准备受控缓存，执行器不把整个数据集一次载入内存。

仅上传清单或已有结果时，报告须分别标明“用户提供清单”“本地执行结果”或“云端执行结果”。指纹用于关联内容，不独立证明身份或授权；不能把客户端声明包装成云端已读取原始信号。

### 云端首版接入硬限制

2026-11-06 补充固定；当前接入策略更新为 `cloud-intake/1.3`，将单文件和单记录上限从 512 MiB 调整为 2 GiB，数据集总量固定为 10 GiB。原策略 `cloud-intake/1.0`、`cloud-intake/1.1`、`cloud-intake/1.2` 及验收记录保留，显式使用旧版本的配置分别执行原有 512 MiB/5 GiB、1 GiB/5 GiB、2 GiB/5 GiB 上限。调整依据与验证见[多模态体积与 2 GiB 接入](../validation/cloud-intake-v1.3-20261106.md)。以下限额适用于云端上传和关联已有云端数据；等于上限允许，超过任一上限直接拒绝本次提交，不进入质控队列。

| 检查对象 | 硬上限 | 计算口径 |
| --- | --- | --- |
| 单个文件 | 2 GiB（2,147,483,648 字节） | 文件实际大小；ZIP 自身体积也须满足 |
| 单份记录 | 2 GiB | 主文件与全部配套文件的总大小；ZIP 按解压后的总大小检查 |
| 单个数据集快照 | 10 GiB（10,737,418,240 字节） | 数据及配套资料总大小；上传量与展开后的逻辑总量分别检查，均不得超限 |
| 单个数据集的记录数 | 100 份 | 按读取器确认的记录数计算，不按文件数计算；原始与派生记录分别计数 |
| 单个数据集的文件数 | 5,000 个 | 按展开后的普通文件数计算，包含表格、标注等配套资料 |

MiB = 1,048,576 字节，GiB = 1,073,741,824 字节，界面使用同一单位。多文件格式不能拆开提交来绕过记录上限。ZIP 沿用每包一份记录的规则；数据集通过目录文件清单组织，不要求整库 ZIP。快照限额按本次完整数据范围计算，不能通过多次续传或复用已存对象绕过。

执行三次检查：上传前按清单预检；服务端按实际文件大小及受限解压重新核验；识别记录与配套关系后，在排队前核验完整快照。关联已有云端数据也走相同检查。只通过网页预检不算接入成功；任何失败都不生成“全部已检查”的报告。

超限提示须明确对象、实测值和上限，例如：“此记录及配套文件共 2.2 GiB，云端当前上限为 2 GiB，请使用本地版。”不得静默截取时长、删除文件或降采样来满足限制。数据集仅可由用户明确选择范围后另建子集，报告标明该子集范围，不声称原始整库已完成检查。

这是一版受控试用的接收边界，格式、结构和方法条件仍独立校验。超过范围使用本地版；云端回传结果按 C 阶段接入。

实施记录（2026-11-06）：单记录上传、ZIP 展开及跨文件合计共用限额核心；本机验证实例可启用 `cloud-intake/1.0`，执行数据集实际目录总量、数量和排队前检查，并保存证据。默认本地目录模式不受云端数据集限额约束。云端 OSS 对象版本、上传完成与续传总量核验仍待实现；本地验证不表示云端已上线。具体见[接入验收](../validation/cloud-intake-20261106.md)。

## 6 阿里云首期部署

```text
浏览器 → 登录与权限 → 数据目录、检查计划、任务与报告
   │                              │
   └─ 临时授权直传 → 私有 OSS ← 云端执行器
                                      │
                                  检查模块

后续：本地执行器 → 允许回传的结果与证据 → 同一工作台
```

首期采用一个云端应用实例和受限后台执行队列，应用与计算在职责上分离，可先部署在同一台服务器。任务状态、输入版本和报告持久保存。之后按实际任务负载扩展执行器数量，不先引入多机集群。

上传使用临时、限范围授权；浏览器直传 OSS，业务服务不转发大型载荷。服务器与 OSS 优先同地域内网访问。账号与项目隔离同时覆盖对象、记录、任务、日志、证据和下载；本地单人版本可以继续仅监听本机使用。

执行端只接受平台支持的模块和受授权的数据来源，不执行用户任意命令或访问任意服务器路径。每个任务有独立临时目录、运行限额和失败清理机制；重试不覆盖已经完成的结果。

### 首期资源预算

以下为有限单位试用的起步配置，初始信号计算并发为 1；调整并发前须按方法峰值和长记录实测重新定额。

| 资源 | 起步配置 |
| --- | --- |
| ECS | x86 Linux，8 vCPU、32 GiB 内存 |
| 工作盘 | 300–500 GB SSD，用于记录缓存、临时文件和运行空间 |
| OSS | 私有存储，先按 500 GB–1 TB 实际存量预算；明确每项目配额和保留策略 |
| GPU | 当前首期不配置 |
| 任务控制 | 先排队执行信号任务；资料检查另设限额，并共同核对 CPU、内存和磁盘余量 |

4 vCPU、16 GiB 可作为公开样例演示的较低配置候选。以上不是全工具箱、长时 Neuropixels 或多任务并发的性能承诺；地域、实例型号和价格在采购前确定。

本地容量参考：2026-11-06，Xeon Gold 6230R，科学计算线程限制为 1。约 1.47 GB、12 份 EDF 的 D01–D03 检查耗时 10.14 秒，进程峰值 44.11 MiB；63 通道、500 Hz、281.66 秒 EEG 的当前信号方案耗时 240.50 秒，峰值 2.45 GiB。后者完成全部时间窗执行，部分子方法因条件不足保持未评；不是完整工具箱或云端压测。具体记录见[容量实测摘要](../validation/capacity-20261106.md)。

## 7 报告与规则维护

数据集报告分别展示资料完整性、一致性问题和信号检查覆盖，可进入个体与记录详情。资料冲突不被高信号分抵消；首版不计算跨个体的统一数据集总分。

记录级信号评分保留规则版本和分项证据。跨记录比较须统一项目、方法参数、评分版本、分析范围及可比条件；未评不补满分。报告的执行状态、自动判断和人工意见分别保存。

检查规则统一登记词条、定义、适用条件、输入输出、阈值来源和验证记录。现有 EEG 试行评分与标准草案沿用各自版本，架构 v1.0 不代表它们已通过专家审核。自动清洗继续作为后续可选模块，保存派生数据和前后报告。

本地执行结果中的文件名、路径、编码、报告正文及波形片段也可能携带敏感信息。回传前使用明确允许的字段与证据清单；原始标识映射保留在提供方。具体模块沿用[敏感字段处理设计](privacy-fields.md)，本地执行不自动等于已脱敏。

## 8 当前实现与分阶段交付

| 阶段 | 交付 | 验收条件 | 当前状态 |
| --- | --- | --- | --- |
| 基础模块 | 独立读取、M 系列信号检查、D01–D03、报告及本机后台执行 | 既有测试与真实数据结果可复现 | 已有；适用边界见各验收记录 |
| A 统一工作台 | 数据归属、总览—个体—记录跳转、共享历史和来源 | 从数据集进入记录检查，无需重新上传；单记录路径仍简洁；旧报告可访问 | 本机登记数据已实现统一目录、总览、记录关联与历史；批量任务及整库网页接入仍待开发 |
| B 云端受控试用 | 账号隔离、私有 OSS、断点续传、持久任务、配额和公开样例 | 两个账号互不可访问对方数据；2 GiB/10 GiB、100 记录及 5,000 文件边界均有测试；断点恢复、失败重试、重启恢复通过；同输入同规则结果一致 | 待实现 |
| C 本地计算接入 | 本地结果包与云端导入，随后增加执行器任务联动 | 原始文件留在本地；回传范围可检查；版本、来源、执行位置与覆盖可追溯 | 待实现 |
| D 扩容与标准验证 | 更多数据/方法、适配优化、可比评分及规则审核 | 代表性数据的耗时/峰值记录、独立参考与专家复核；规则变更可追溯 | 持续进行 |

先完成 A，再开放 B 的受控试用；C 不作为公开样例试用的前置条件。B 开放前先用公开数据完成隔离和运行验收。云端改造不默认授权上传医院原始数据。

首页已合并入口，保留旧 URL 兼容。数据集已支持按个体/会话打开记录、直接进入信号检查、查看关联运行历史并返回所属数据集；原文件只读就地访问，未复制整份波形。清单版本、来源指纹与记录归属随确认和任务保存。整包网页上传、OSS、跨单位执行器和统一父子任务关系均尚未接入。现有[数据集规则](../dataset-checks.md)与[工程验收](../validation/dataset-consistency-20261106.md)继续有效。

## 9 版本维护

本版作为第一份固定基线保存，实施进度记入 [TODO](../../TODO.md) 和 [CHANGELOG](../../CHANGELOG.md)。改动入口层级、数据关系、模块边界或计算位置时，新建后续设计版本，列出变更原因、兼容影响与旧数据处理方式，再更新文档入口。排版和错字修正可直接维护，不静默改写已固定的产品决策。

单文件、单记录、数据集快照大小及记录/文件数量按第 5 节 `cloud-intake/1.3` 固定。暂未固定的实施参数包括部署地域、具体月费、账号/项目累计存储配额、保留期限和扩容阈值。这些参数由试用范围与压测确定，不影响本版的统一工作台和两类执行位置。后续放宽接入限额须完成相应容量测试并另立策略版本。
