# 数据入口与结果汇总 v1

实现契约：`data-library/1`、`dataset-overview/1`。2026-11-06。

落实[顶层设计 v1.0](platform-v1.md)的 A 阶段，不改变 D01–D03 检查规则或 EEG 评分公式。

## 1 入口与层级

```text
质控台首页
├─ 上传一份记录 → 提取信息 → 确认 → 信号检查 → 报告
└─ 已有数据（同一目录）
   ├─ 单份记录 → 原有记录工作台
   └─ 数据集 → 结果总览 → 个体 → 记录 → 信号检查与报告
```

不再要求先选择“单份记录 / 数据集”模式。已有数据目录默认收起，展开后可搜索，先显示六项；数据集内记录在所属个体下面显示，不重复塞入首页。单份记录保留最新确认版本；旧任务链接仍打开其冻结输入。

本版数据集仍由本机配置登记目录与应有清单。网页单记录上传和 ZIP 配套文件规则不变；整库网页接入、OSS 与云端账号隔离仍属 B 阶段。

## 2 总览内容

| 层级 | 展示内容 |
| --- | --- |
| 数据集 | 文件与清单相符数、需核对资料的记录数、已有信号报告数；先显示具体事项与建议下一步 |
| D01–D03 | 保留简洁检查范围图，规则编号和状态明细置于展开层 |
| 个体 | 记录数、资料待处理项、已有报告、未运行记录 |
| 记录 | 相对路径、会话、模态、原始/派生、资料检查结果、最新信号检查状态、范围与分项、报告和历史 |
| 明细 | 冲突、复核、未评的原始检查词条、影响文件与证据 |

EEG 分数按记录展示，注明评分版本与分项。其他模态沿用描述性结果。没有计算的记录显示“尚未检查”；数据集资料检查未完成时不显示零问题或通过。不计算跨个体总分，也不对不同比较组排序。

“整段已计算”只统计：整记录方案，已计算时长覆盖总时长，失败、未执行和来源时间缺口均为零。部分子方法未评仍单列。计算覆盖不是质量合格率。

## 3 结果关联与来源

1. 数据集资料结果选择当前清单的最新一次尝试；失败不回退为旧成功结果。
2. 信号结果按数据集 ID、清单指纹、记录 ID 关联，选择该记录最新一次尝试。只列与此来源对应的运行。
3. 对照信号任务冻结输入中的主文件及配套 SHA-256，与资料检查保存的文件清点结果比较。来源不一致时标记复验，旧报告仍可打开，但不计入当前已有报告数和分数。
4. 尚无资料检查结果或来源指纹时，明确“待资料检查核对来源”。独立信号报告仍可查看，不伪称来源匹配。
5. 资料检查按明确记录 ID 或已声明配套文件关联到记录；一个文件缺失不会自动把整组所有记录标坏。无法归属的发现保留在数据集明细。
6. 历史清单总览使用当时的范围与比较组，不套用当前清单。信号结果采用该清单下最新保存尝试，并注明生成时间；这不是整个页面在历史某一时刻的快照。打开当前原文件须返回当前汇总。

查看/刷新总览只组合保存的结果，不扫描整库波形，也不重新证明当前磁盘文件未变。要检查修改后的数据，须重新运行资料检查和相应信号检查。原件、历史证据与原有报告不改写。

## 4 接口与导出

| 接口 | 内容 |
| --- | --- |
| `GET /api/v1/data` | 数据集及独立记录目录，不暴露本机绝对目录 |
| `GET /api/v1/packages/{id}/overview` | 当前汇总 JSON |
| `GET /api/v1/packages/{id}/overview?job={id}` | 指定资料任务清单下的汇总 |
| `GET /api/v1/packages/{id}/overview/report` | 可打印的独立 HTML 汇总报告 |
| `GET /api/v1/packages/{id}/overview/report?download=1` | 下载 HTML；可另加 `lang=en` |

导出包含记录分项、资料发现、清单指纹、资料任务及信号任务 ID。不是自动 PDF 导出；已有记录级 PDF 功能保持不变。个体编号、相对文件名和报告内容仍可能敏感，不能把此导出视为自动脱敏。

## 6 面向使用者的呈现

2026-11-06 更新：首屏按“当前结果—需处理事项—记录报告”组织；按个体汇总、历史、比较设置与技术证据默认收起。不能把所有情况概括为“冲突”，也不要求临床使用者先理解 D01–D03。

汇总增加 `attention_groups`：按原检查词条和状态分组展示，保留全部 `check_ids`，不宣称这些是去重后的独立根因。每组写明问题、涉及记录、建议下一步与建议核对方。数据集示例的七条 conflict 可显示为两类：一份无法读取，六份单位标注不一致；原检查结果与评分不变。

点击“查看相关记录”过滤记录列表；点击“查看依据”展开对应证据。未知条件保留为“尚无法判断”，不混入已检出问题；没有运行显示“尚未检查”。后续需邀请真实使用者完成任务走查，这次文案与结构调整不等于医生可用性已获验证。

## 7 演示与信息层级

首页常显上传入口、模块图及最多四个已完成示例报告。进入具体记录后，示例报告自动收起，空间用于该记录的提取信息与结果。已有数据、运行记录、工具箱默认收起；不会因打开已完成的历史报告而自动展开整列运行明细。进行中的任务仍展示进度与取消操作，逐模块执行明细不因轮询反复展开。

`demo_examples` 在本机配置中明确指定示例：记录示例绑定实际任务和输入，显示冻结任务的报告；数据集示例读取当前清单下各记录的最新结果。任务没有完成、报告缺失或输入不匹配时，不生成假链接。克隆安装没有计算结果时，不显示示例卡；不附带本机数据、运行编号或预设分数。

`validation_library_ids` 仅按显式 ID 将缺件、人工修改和兼容性验证案例放入目录的“验证样例”。不按分数、失败状态或异常数自动筛选。用户新上传的异常数据仍属于普通目录，原报告与问题保留。数据集中的问题名称常显，解释和建议折叠；记录已有报告时，“查看报告”作为首要操作，“打开记录”用于继续检查。

配置示例和准备公开双个体样例的方法见 [工作台说明](../../apps/workbench/README.md)。本次只改善发现结果和逐层阅读的路径，不修改检查规则或评分，也不将演示结果当作专家确认的质量真值。

本次真实数据与报告摘要验收见[演示入口验收](../validation/demo-reports-20261106.md)。
