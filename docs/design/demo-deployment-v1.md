# 在线演示版部署方案 v1.1

版本：`demo-deployment/1.1`。更新：2026-11-11。状态：012 已部署；整理同址云端部署配置，云服务器待提供。详见[部署说明](../deployment/demo.md)。

本轮目标是把现有本地质控台放到服务器上供展示和试用。保留现有页面、算法模块和报告，只做运行环境与访问地址的必要适配。

本方案替代 [platform-design/1.0](platform-v1.md) 中作为首期前置要求的账号、项目隔离及 OSS 等云平台建设安排；旧设计保留作后续参考。数据层级、模块接口和评分规则继续沿用现状。

## 1. 展示与操作

| 入口 | 演示版行为 |
| --- | --- |
| 示例数据集 | 直接打开预先缓存的 EEG、ECoG、sEEG、Neuropixels 报告；管理员可维护用于实际运行的公开样本 |
| 上传与检查 | 沿用现有上传、信息确认、方案选择、权重设置和后台计算流程 |
| 我的数据 | 全站共享目录，所有访客上传并检查的记录及报告都放在这里；入口仍名为“我的数据”，不附加“共享”标签 |
| 数据与方案 | 相同数据归在一起，下分不同质检方案及历次运行；质检名称继续可填写或自动生成 |
| 报告 | 沿用分项、综合分、候选定位、图表和 PDF；网页打开时读取已保存结果 |
| 模块协作 | 同一网址的 `/flow/`，查看无需账号；团队密码编辑，保存草稿、批注、附件与固定版本 |
| 管理员 | 仅一名管理员维护示例、清理共享数据、查看服务状态；优先使用部署配置与维护命令，不另建管理后台 |

访客无需注册或个人账号。所有访客可查看同一份“我的数据”，上传入口只需清楚提示“演示区文件与报告对所有访客可见”。管理员的维护操作单独授权，凭据由部署环境设置，不写进代码或浏览器脚本。

预先缓存的报告可以直接查看；重新计算需要服务器上的实际样本或新上传文件。不会把只有报告快照的数据显示为可重新运行。

## 2. 最小部署

```text
浏览器 → 统一网址
          ├─ /       → Python 质控服务 → 模块、数据与报告
          └─ /flow/  → Node 协作服务   → 草稿、附件与固定版本
```

一台 Linux 服务器，一套现有 Python 环境及 Node.js 24。两个服务由同一反向代理提供访问，数据放在各自的持久目录。网页、接口和计算沿用现有代码；必要的 HTTPS 入口和服务自动启动交给部署配置。先使用现有安装与启动脚本，容器可后补，不作为演示前置条件。

模块目录由质控代码生成，随部署同步。协作编辑只修改讨论稿；要影响实际运行，需修改并验证质控代码。更新不覆盖团队说明、附件或历史版本。

后台先按现有队列逐个运行，保留任务状态和结果。服务重启后，未完成任务继续显示中断并允许重新提交；本轮不开发自动断点恢复或分布式任务系统。

| 限制 | 约定 |
| --- | --- |
| 单文件 / 单份记录 | 2 GiB；配套文件合计及 ZIP 展开后也须满足 |
| 数据集 | 10 GiB、100 份记录、5,000 个文件；演示先使用管理员预置的数据集 |
| 上传副本 | 7 天；运行中延后清理，报告和检查证据保留 |
| 运行控制 | 先逐个计算，保留现有排队数量与文件限额；磁盘不足时拒绝新上传 |

网页整库上传、OSS 直传、分片续传、用户/项目体系、远程本地执行器、多机调度均不列为本轮交付前置条件。

## 3. 完成的判断

1. 换一台电脑打开网址，能直接看到四类示例，报告、图表和 PDF 都能打开。
2. 上传一份文件，确认信息、选择方案后能完成计算并查看报告。
3. 另一浏览器能在同一个“我的数据”中看到该记录和报告；同数据的不同方案关系清楚。
4. 重启服务后，已有数据与报告仍在，中断任务可重新提交。
5. 两个页面相互跳转保持当前网址；密码编辑、附件、固定版本及重启保留可用。
6. 普通访客不能执行管理员清理或维护操作；7 天清理保留报告。

主要交付仍是质控模块、配置规则、标准草案和示例报告。部署工作以让这些内容可访问、可操作、可展示为界限。
