# 数据保存与公开来源

规则版本：`public-only/1`，2026-11-13。

## 1. 两类数据

| 类型 | 可见范围 | 保存方式 |
| --- | --- | --- |
| 已发布的公开示例 | 所有访客，在“示例数据集”查看 | 保存来源和检查报告；管理员配置公开源文件后支持对应的信号读取 |
| 用户上传 | 仅提交它的浏览器 | 临时显示在“我的数据”，带清理倒计时；不进入公共目录或示例缓存 |

“我的数据”只列出当前浏览器的临时上传，新访客初始为空。服务器预置的公开测试记录不自动合并进此列表；既有文件和报告仍保留，供已发布示例或原有报告链接使用。

访客可在“我的数据”的条目菜单中删除自己的临时数据及报告，或单独删除一次报告，无需密码。正在运行的任务先停止，再清理文件。也可点击“结束并清理”清空本浏览器会话；不影响其他浏览器。临时上传不提供归档。

公开记录和报告仍禁止访客归档、恢复或删除。示例数据集菜单的“删除示例”要求重新输入模块协作编辑密码；后台验证通过后从公开目录撤下示例，同时禁止访问对应缓存报告、PDF 和波形链接。此操作对全部访客生效，不删除上游公开数据。撤下清单保存在运行数据目录的 `public-example-state.json`，更新软件后仍保留；随软件分发的只读示例包不改写。

上传文件即使与公开样本相同，也仍是临时上传。填写来源说明不能使它进入公开目录。

“临时”并非完全不写磁盘：读取、计算及波形展示需要临时工作文件。服务用随机 HttpOnly 会话 Cookie 控制访问，不需要注册账号。跨浏览器直接打开临时记录、报告、PDF 或波形地址会被拒绝。

## 2. 清理时间与范围

- 点击 **结束并清理**：停止本会话未完成任务，进程退出后删除本会话数据。
- 已生成报告：最后一项任务结束后 **1 小时**清理，继续看报告不会延长此期限。
- 尚未运行：闲置 **30 分钟**清理。
- 每个临时会话最长 **6 小时**，到期停止任务并清理；不能无限续期。
- 服务异常退出：下次启动先清理上次临时工作目录。正常停止服务也执行清理。

“我的数据”时钟图标显示服务器给出的到期时间，浏览、轮询和刷新均不续期。计算中显示“完成后保留1小时”，仍受6小时上限约束。同一浏览器会话的上传共用清理期限，全部临时文件与报告同时清理。浏览器 Cookie 丢失后无法找回临时会话，但服务器仍按期清理。

密码验证复用模块协作服务，无额外账号。源码部署由 `admin_auth_url` 指向内部 `/api/access`（默认 `http://127.0.0.1:18770/api/access`）；Compose 已配置 `QC_ADMIN_AUTH_URL=http://flow:18770/api/access`。独立启动质控台时，需同时启动模块协作服务才能删除示例。密码错误、验证服务停机或未配置密码时，删除被拒绝，现有示例保留。

清理包括上传文件、解压文件、读取信息、信息修订、任务请求、算法临时文件、运行日志、结果、图表、报告和复核记录。网页刷新不立即删除，关闭网页不作为可靠的删除触发器。需要留存时由用户下载报告；浏览器下载文件不受服务清理影响。

临时工作目录为 `data_dir/.temporary/`，目录权限 700。禁止将其纳入备份、镜像或示例发布；代理不缓存响应、不记录请求体、Cookie 或上传文件名头。应用删除不保证清除磁盘历史快照，部署方须分别设置快照范围。模块协作的团队附件和版本采用独立保存规则，不属于质检上传。

## 3. 管理员登记公开数据

新安装默认启用本规则。旧服务在配置中显式启用，未启用的旧配置仍使用原保存行为。

```json
{
  "data_policy": "public-only/1",
  "public_records": {
    "eegmmidb-s001r01": {
      "name": "PhysioNet EEG Motor Movement/Imagery Dataset",
      "url": "https://physionet.org/content/eegmmidb/1.0.0/",
      "version": "1.0.0",
      "license": "Open Data Commons Attribution License v1.0"
    }
  },
  "public_packages": {}
}
```

`public_records` 的键为已配置记录 ID 或记录家族 ID；`public_packages` 的键为已配置数据集 ID。两者保存来源名称、原始数据页、版本和许可。多来源数据集使用 `{"sources": [{...}, {...}]}`。原有输入路径、读取配置和数据集清单继续使用已有结构。

管理员应核对下载凭据、内容指纹及配套文件，检查展示名称、说明与报告没有额外私人信息，再登记。不能依据文件名或用户填写的链接直接认定为公开数据。来源会显示在数据条目下，不要求用户展开技术详情才能找到。

## 4. 旧记录迁移

先核对来源，再开启规则。未登记的旧输入、报告、数据集及其运行入口停止对外提供，不能仅从首页隐藏。历史文件不会因开关改变而直接删除：管理员应核对清单后清理不再保留的上传副本和报告；外部原始研究文件不在自动清理范围内。

部署迁移只携带已确认公开的数据、报告及来源配置。已发布示例必须带来源与许可；只提供当前发布清单中的缓存文件。更新保留算法结果，不因保存规则变化重新计分。
