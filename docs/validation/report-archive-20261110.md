# 按报告归档验证 · 2026-11-10

## 操作规则

- 最小单位是每次检查产生的报告或已结束的运行记录。单文件、数据集资料检查及数据集内的信号检查分别有独立标识。
- 报告右侧操作菜单提供归档；归档内提供恢复及彻底删除。按数据与方案组织，历史运行也可单独操作。
- 当前列表仅显示未归档报告；归档列表仅显示已归档报告。同一数据可以同时出现在两边，输入仍可用于新检查。
- 数据行“归档全部”继续作为整组操作；从整组归档中单独恢复一份报告时，其余报告保持归档。
- 单报告删除只移除本次检查记录、结果、图表、导出报告及对应复核记录，保留输入、同数据的其他方案及历史报告。
- 先预览删除范围再确认。清空归档可以同时包含完整数据条目和独立报告，输入副本只有整组删除时才进入清理范围。
- 正在执行的任务或活跃批次中的报告不能删除。复验报告仍引用的基线不能单独删除，可以将关联报告全部归档后一起清理。
- 服务端归档及删除标记持久化。旧版整组归档兼容；删除后重启不会恢复已删除报告。

## 验证

Python 回归 **120 项测试、34 项子测试通过**，覆盖归档层级、删除范围、旧记录兼容、重启、共用文件、数据集与审核逻辑。其中新增验证：

1. 同一数据归档一份报告后，其他方案及输入仍在当前列表；配置恢复选取未归档的最近一次运行。
2. 删除单份报告时，其 PDF、图表及结果文件被移除，其他报告与输入内容保持不变。
3. 从旧版整组归档恢复单份报告，其余报告保持归档；恢复整组时所有报告恢复。
4. 清空混合归档时，独立报告所属输入得到保留。
5. 批次内删除已结束的子报告，其他子报告仍可访问；活动批次阻止删除。
6. 数据集资料报告与信号报告分别归档；复验基线的删除约束有效。
7. HTTP 接口验证归档后的目录、历史、报告访问及恢复。

前端数据目录交互测试覆盖当前与归档分离、同方案历史展开、单份报告操作、部分归档的整组恢复和删除确认文案。界面契约 168 项、中英文 30 项、版面 15 项及数据集交互检查通过。

## 部署与边界

本地及 012 同步同一版本。部署前无运行任务，部署后检查目录及报告数量保持不变；每份报告均返回独立操作标识。未归档或删除用户现有报告。

测试使用隔离临时文件及报告，未重新运行质检算法、修改评分或改写原始报告。本次未进行浏览器视觉验收：此前本机页面的已保存访问权限仍为阻止，不通过其他浏览器路径绕过。
