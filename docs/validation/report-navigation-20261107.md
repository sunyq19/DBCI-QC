# 报告定位、跳转与布局修正

2026-11-07 · `1.0.0rc3.dev20` · 本地验证

## 本次修正

| 用户遇到的问题 | 原因与处理 |
| --- | --- |
| 展开工具箱、模块或接触点表格时页面宽度变化 | 页面滚动条占位不一致，网格受内容最小宽度影响。统一预留滚动条，固定主栏比例，表格在自身区域内滚动。 |
| 报告松散，技术文字抢占重点 | 改为报告概览、检查结果、问题定位、图表分析、方法与依据。压缩字号、间距和边框层级；SHA、运行编号和计算细节放入折叠区。 |
| 不清楚异常在哪个通道、哪个时段 | 定位表给出真实通道标识和原记录时间；点击条目切换对应原始波形，阴影标记候选区间。仅使用已有检测证据中的位置。 |
| 新结果回退到旧版冗长呈现 | 首页补充识别 `eeg-report-view/6`，使用已有紧凑报告组件。 |
| 图表跳转失败或定位不生效 | 缓存发布保留页内锚点；补齐已声明的基础图表；跳转时展开对应图表；嵌入图表返回报告时离开 iframe。 |
| 示例链接看似可点，却没有文件 | 未发布的证据文件改成非链接文字，不再伪装成跳转到快照说明的入口。 |
| 实际运行的图表页首次打开超时 | 直接读取保存的报告摘要，跳过通用结果摘要对大候选索引的逐项遍历。 |
| 导入提示难理解 | 首屏区分一份文件和多份记录 ZIP；配套文件要求及七天保留期放入文件要求。 |

## 2026-11-07：加载缓存与灵犀云缺分修复（dev23）

### 复现与原因

- 用户提供的 `dc439d321cf540b4a573724b8c9d41b9/report-focus-7.png` 在本地 HTTP 检查中返回真实 PNG，对应 F5 的 242.75–244.25 秒高频候选。未在浏览器中复现点击失败，不能把接口成功当成视觉验收。
- 原交互在图片生成完成后才滚动到预览；现在点击即定位预览并显示载入状态。完成报告时预生成定位图，后续点击读保存的图片；失败生成不缓存为成功。
- 图表展开时原先重复解析大型 M04 检测文件。现在分层缓存精简证据、图表页面及报告摘要，检测结果和显示代码变化时自动失效；不同图表与波形请求互不阻塞。该缓存不重新计算分数，也不替代原始证据。
- 图表的 21 个图标题旁已无来源链接或作者姓名；仅在“方法来源”折叠区保留一次相应项目链接。

### 灵犀云缺分的两个独立问题

旧任务覆盖 733 秒，切成六个 120 秒窗口和一个 13 秒尾窗。

1. 频域方法仍要求伪差补集中存在持续时间严格大于 10 秒的片段。独立的 13 秒尾窗没有满足条件的片段，导致 PSD 差异等项目未评。新的分段策略在检测前将最后 133 秒均分成两个 66.5 秒窗口；原始样本无遗漏、无重复，不跨采集缺口。两段分别有约 66.33 和 54.59 秒满足频域取样条件。
2. 高频功率统计在尾段发生一次 float64 指数溢出。原版函数产生无穷值，原适配器因此拒绝整项计算。现在只在出现溢出时、在独立子进程内扩展原版指数运算精度，继续调用原版阈值和区间函数；不裁剪大值、不删除异常通道、不调整阈值或评分公式。NaN、平台精度不足或重试后仍非有限，继续报告未评。

`gnosis_worker.py` 保存数值适配模式和溢出数量；不改安装的上游 wheel 或 NumPy 全局模块。新结果属于含数值适配的运行版本，不称为未修改原版二进制的逐位复现。

重跑记录：`c0230a5a6ee64f079257ccd18e4656a6`。前五个未改变边界的窗口共 40 份灵犀云方法结果，测量值及候选位置与旧任务完全一致。旧任务与原始结果保留。
