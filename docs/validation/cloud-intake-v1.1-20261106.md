# 多模态体积与 1 GiB 接入策略

日期：2026-11-06。当前策略：`cloud-intake/1.1`；旧 `cloud-intake/1.0` 保留。

单文件、单记录含配套、ZIP 展开上限均调整为 **1 GiB = 1,073,741,824 字节**。数据集保持 **5 GiB、100 份记录、5,000 个文件**。默认本机网页上传采用新上限；显式配置旧 1.0 的实例仍采用 512 MiB，历史报告及接入证据不改写。

## 1 为什么调整

现有小样例可以验证读取与流程，不能代表完整实验的体积。体积主要取决于通道数、采样率、每样本存储字节数和时长，模态名称本身不能决定大小。格式转换、压缩、保存数据类型及容器内其他内容也会改变体积。

未压缩连续电压的近似计算：

`字节数 ≈ 通道数 × 每秒采样数 × 每样本字节数 × 秒数`

下表是用于规划的配置估算，均按 16 位、每样本 2 字节，忽略少量文件头，不是各模态的统计均值。

| 示例配置 | 1 小时体积 | 1 GiB 约可容纳 |
| --- | ---: | ---: |
| 头皮 EEG：64 通道、500 Hz | 0.215 GiB | 4.66 小时 |
| ECoG/sEEG：128 通道、2,000 Hz | 1.717 GiB | 35 分钟 |
| Neuropixels LF：384 神经通道 + 同步通道、2,500 Hz | 6.454 GiB | 9.3 分钟 |
| Neuropixels AP：384 神经通道 + 同步通道、30,000 Hz | 77.449 GiB | 46.5 秒 |

若保存为 32 位浮点，上述体积加倍；64 位浮点为四倍。NWB 是容器格式，可能保存多个信号流及其他内容，不能单独给出一个“典型 NWB 大小”。

Neuropixels 示例的 16 位、384 神经通道加同步通道以及 AP/LF 存储方式见 [SpikeGLX 官方手册](https://github.com/billkarsh/SpikeGLX/blob/master/Markdown/UserManual.md#imec-channels)。作为较低数据率的临床 EEG 参照，[CHB-MIT 官方说明](https://physionet.org/content/chbmit/1.0.0/)给出多数记录 23 通道、256 Hz、16 位；这与本地约 40 MiB 的 1 小时文件相符。

## 2 本地样例复核

文件大小由本次文件系统核对；时长、采样率和通道数来自已有读取器登记信息，属于这些样例的技术描述。

| 样例 | 记录信息 | 实际记录大小 |
| --- | --- | ---: |
| CHB-MIT chb01_03 | 23 通道、256 Hz、1 小时 | 40.44 MiB |
| MNE ECoG BrainVision 配套文件 | 98 通道、1,000 Hz、269.08 秒 | 100.60 MiB |
| 同份 ECoG 的 FIF 版本 | 同上 | 201.20 MiB |
| MNE sEEG FIF | 119 通道、约 999.41 Hz、60 秒 | 27.24 MiB |
| Neuropixels LF 样例 | 385 通道、2,500 Hz、5.27 秒 | 约 9.68 MiB |
| 人类 Neuropixels AP 片段 | 385 通道、30,000 Hz、2 秒 | 约 44.08 MiB |

BrainVision 主文件 `.vhdr` 很小，必须计算配套二进制等文件合计。两个 ECoG 版本的体积不同也说明，不能仅根据时长或模态判断上传容量。

## 3 产品边界

1 GiB 可改善短时 EEG 和部分颅内记录的试用覆盖，但不能覆盖完整 Neuropixels AP 或多日监测。超过上限仍明确拒绝；用户可选择有清楚时间范围的片段演示，报告只评价所提交片段。完整大数据通过本地目录/CLI 运行，后续接入云端回传结果。

提高接入上限不提高分析时窗的内存预算，不意味着把 1 GiB 文件全部读成内存数组。原有最长 120 秒、原始读取预算 256 MiB 的分窗策略保留；算法额外内存及运行时间需单独验证。1 GiB 是接收上限，不是全工具箱的性能保证。

## 4 版本与验证记录

共用策略、上传与解压、登记任务、前端提示、中英文说明及边界测试同步更新。新增策略不会把旧 1.0 配置静默升级；重启后默认本地网页上传使用 1 GiB。云端仍未部署，OSS 完成上传、续传和权限隔离继续按 TODO 实现。

实际接收测试：生成一份 64 通道、512 Hz、4 小时的合成恒值 EDF，以最多 1 MiB 的块逐段送入接收器，完整落盘并经过原生读取器提取信息。文件为 943,735,040 字节（900.016 MiB），1.1 接收成功并进入待确认状态；1.0 在读取请求内容前拒绝。该次接收与提取耗时 9.43 秒，进程峰值 RSS 37.57 MiB。临时文件已清除。该测试不包含网络传输、完整信号质控或临床有效性验证。

精确上限与上限加 1 字节、记录配套合计、解压超限、5 GiB 数据集以及旧策略兼容分别由边界测试核验；900 MiB 示例不替代所有格式及算法的容量测试。

自动回归通过：545 项 Python 测试、142 项纯 JavaScript 检查、30 项本地化检查、15 项文档导航检查、12 项静态布局检查及数据集界面状态检查。当前本机服务已重启，`/api/v1/catalog` 返回上传与单记录上限均为 1,073,741,824 字节、版本 `cloud-intake/1.1`；首页静态提示同步为 1 GiB。这是接口及静态页面核验，不包含浏览器视觉验收。

旧实现和真实数据流程验收见[1.0 验收](cloud-intake-20261106.md)。本轮独立验证记录保存在仓库忽略目录 `.local/admission-v1.1-20261106/`，其中 `large-intake.json` 保存接收测量，`sample-sizes.json` 保存上述非 EEG 样例的实际配套总量。
