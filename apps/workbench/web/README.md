# 本地工作台界面

无需构建或前端依赖。由工作台服务将本目录作为静态资源根目录提供，入口为 `index.html`。请通过本地服务的 HTTP 地址使用，直接双击 HTML 无法连接分析 API。

- `index.html`：中文工作台、配置表单、模块详情与运行区域。
- `styles.css`：响应式蓝色浅色界面，无远程字体或样式依赖。
- `app.js`：Toolkit、文件读取/确认、方法推荐、计划、任务、取消、结果和报告交互。
- `check-ui-contract.mjs`：使用最小 DOM 替身的纯 JavaScript 配置与呈现契约检查，不启动浏览器或分析任务。

首页导航另有“质控标准”，进入同源 `/standards` 独立文档页。文档正文由服务读取 `docs/qc-standards.md`，提供目录、Markdown 下载及打印；不向首页增加长说明，也不参与上传、推荐或运行状态。维护正文只编辑该 Markdown 源文件。

每个模块弹窗标题下直接提供“详细介绍”，打开 `/standards/modules/M01` 至 `/standards/modules/M09` 的新标签页（`noopener noreferrer`），保留当前工作台草稿。工具箱卡片仍进入所属模块弹窗。标准页的“返回查看模块”使用 `/#module-M01` 等链接：目录载入后及 `hashchange` 时只打开对应说明，九个模块在没有数据时均可查看；不会选择输入、请求推荐/计划或启动任务。只接受精确的 `M01`–`M09`，其它 hash 安全忽略；关闭弹窗时以 `replaceState` 清除合法模块 hash，保留路径与查询参数，不跳回其它页面，也不触发循环。

API 使用同源 `/api/v1` 前缀：`catalog`、`intakes`、`intakes/{id}`、`intakes/{id}/confirm`、`recommend`、`plan`、`jobs`、`jobs/{id}`、`jobs/{id}/result`、`jobs/{id}/report` 和 `jobs/{id}/cancel`。取消请求为 `POST {}`。所有输出按文本转义；原始通道索引和完整配置原样保留，不根据名称确认角色，也不按同名通道合并。

默认流程是 **读取本机 EDF → 确认识别结果 → 检查方案 → 开始检查**。初次加载只请求目录与历史记录，`state.input` 保持 `null`，不选首个示例、不推荐、不规划、不创建任务。首页以本地文件选择和“读取文件”为主；检查工作区、元数据、高级设置和空结果隐藏。已登记记录保留在次要的默认关闭区域，旧的场景卡容器保留但不渲染卡片。

选择本机文件立即清除旧草稿、计划和结果视图，推进异步请求版本；读取、待确认或读取失败时不能误跑先前文件，也不会自动恢复旧选择。读取成功后仅显示文件格式、大小、通道、采样率和建议选道摘要。用户明确确认后登记文件，随后自动请求推荐、采用可用配置并核对计划；只有明确点击“开始检查”才调用 `POST /jobs`。明确选择次要区域中的已登记记录时，也会准备该记录的方案。

确认文件后的操作区保留文件摘要、必要阻塞说明和开始按钮；检查模块在常驻流程图中展示，默认增强清单放入推荐详情。来源、标签、背景、时间、通道配置与方法工具箱默认折叠；验证限制见对应模块说明页；高级设置包含手动模块、扩展、参数 JSON 及推荐/采用/核对按钮。推荐理由、复核重点、非必需字段、方法来源和原始依据也默认折叠。Toolkit 仍可按通用/条件/可选和已接入/待接入筛选目录，不暗中排除方法。模块弹窗先展示摘要、输入、输出和依赖，详细原理、适用条件、证据、许可及参数需展开查看。仅 HTTP(S) 来源可点击；仓库源码路径保留为文本。

读取本机文件使用 `POST /intakes` 二进制内容、`application/octet-stream` 与 URL 编码的 `X-Filename`，上限 512 MiB，不向外部服务上传。角色建议预填，主视图显示建议 EEG/辅助信号数和采样率；逐道索引、单位、采样率和角色表默认折叠，无 EEG 或建议选道采样率不一致时展开要求调整。用户必须主动勾选“这是头皮 EEG，使用当前识别结果”的批量确认，才能提交 `modality: scalp_eeg` 和所选角色；这个未默认勾选的声明不代表系统推断了模态。未知参考与临床背景保留未知，每种辅助角色最多一条，EEG 和辅助导联必须具有一致的原生采样率，服务继续核验单位等条件。登记后自动准备方案，但不启动分析。待确认读取编号保存在当前浏览器会话，可恢复；超时或失败不自动重试上传/确认。

`POST /recommend` 只提交 `input_id` 和完整 `qc_config`。默认流程仅在 `can_apply: true` 且响应完整时采用推荐，然后独立调用 `/plan`；推荐携带的计划标识不直接启用运行。推荐失败、条件不足或计划核对失败时默认开始按钮保持禁用，主区提供重试入口。手动修改时段、背景、模块、扩展或参数会作废旧推荐和计划并标记“手动方案”，保留用户选择，不静默恢复自动方案。此时点击主“开始检查”会在同一次明确操作中先核对最新计划，成功后再创建任务，无需另点预览。未应用的参数 JSON 会在开始时校验并应用；无效时显示主区错误并展开高级设置，不运行。点击“恢复推荐方案”才重新采用推荐，保留当前选择的时间窗口和显式参数。

异步响应由单调递增的草稿版本和计划请求编号保护，包含 A→B→A 切换、手动编辑和历史任务切换；文件读取、确认及目录请求还保留各自版本，较旧响应不能覆盖新文件或错误状态。文件待确认和自动准备期间开始按钮禁用，显式开始提交期间还锁定输入切换和配置变更，避免重复提交。初次目录加载不自动切到历史任务；只有点击历史记录才查看保存的方案。切换回输入会清除旧结果视图，不取消服务端已有任务，历史记录仍可再次打开。历史读取期间和失败时都不补用当前草稿的来源、标签或计划。

计划请求和任务请求带完整 `qc_config`。草稿从所选输入的默认配置初始化，保留未修改字段，并记录显式采用的推荐和参数修改；配置变更使原计划失效。运行前需成功规划。一次分析最长 120 秒，超出记录范围或无 EEG 索引时在提交前阻止。模块适用性、依赖闭包、执行与落盘均由服务端负责。

界面不生成模拟结果，不将请求超时当成任务失败，不自动重试提交；状态轮询失败时保留最近一次已知状态并重试。只有成功读取已完成任务的真实结果后，才提供实际报告入口。总分始终明确为尚未校准；M05 历史完整记录对照与当前时段结果分开展示。

计划可能始终包含九个节点，未选节点的服务原始状态为 `skipped`。界面以 `plan.selected_modules` 为选择依据，将这些节点显示为“未选择”，与已选模块因条件不足而“已跳过”分开。执行进度分母只包含所选模块；原始服务状态和原因保留在详情中，不改写结果 JSON。

数据标签优先展示当前计划保存的 `data_tags`，草稿展示输入来源及明确的人工背景补充。技术标签只读；疾病、年龄组和任务使用目录提供的选项。未知保持未知，换记录时恢复该记录的默认背景和配置，再按新记录自动准备推荐。查看历史任务时，标签和方法适用性取自该任务的计划，不借用当前草稿的数据。

模块详情保留原有功能、输入、输出和依赖，并补充通用、条件、可选方法、适用条件、开源来源、许可、参数与限制。已接入的通用和条件方法随顶层模块执行；扩展开关动态取自目录中 `optional_extension: true` 且 `implementation: "available"` 的方法，不维护前端方法 ID 白名单。启用扩展同时选中父模块，取消父模块会明确关闭相关扩展。可用性由 `method_applicability` 决定，尚未接入、未选择、条件不足和待规划分开展示。

输入的 `provenance: {name, url, version?, license?}` 和 `data_usage: {typical_use, annotations, annotation_limits}` 在选数区显示来源链接、典型用途、已有标注及其边界。后者三项使用简短文字；界面不据疾病或任务标签补出标注结论。有效计划优先使用冻结的 `input_provenance`、`input_data_usage`；历史任务仅使用 `job.plan` 中的这两个字段，缺失时显示未记录，不借用当前目录元信息。

结果区的“实际扩展结果”只取 `result.extensions`，显示中文执行状态、原因和已报告的候选数量。缺失数量不补零；只有总数时不将其擅自解释为时间段数或坏通道数。明确的 `candidate_interval_count`、`candidate_channel_count`、`candidate_pair_count`、`candidate_epoch_count` 分别展示为时间、通道、通道对、分析分段候选，不自动求和；时间／通道兼容原有别名。通道对数不等于坏通道数，分析分段不自动等同任务试次。历史结果没有此字段时不从计划补出执行结果；计划的 `ready` 不当作执行完成。模块与扩展的原始 JSON 都保留在折叠详情中。

本地静态检查：

```sh
node --check apps/workbench/web/app.js
node apps/workbench/web/check-ui-contract.mjs
```

纯 JavaScript 检查覆盖空白上传首页、陌生文件名的读取与确认、新文件清除旧任务视图、旧读取/确认响应隔离、自动准备、手动保留、推荐拒绝、A→B→A 与旧请求隔离、单次开始、上传确认、历史来源、折叠标记及九个模块的只读深链接、非法 hash、关闭与草稿保留；不创建真实分析任务。它不能代替浏览器布局、键盘和视觉验收。

## 常驻流程图

桌面采用左侧文件/操作、右侧流程图的两栏布局。图示独立于隐藏的检查工作区，始终可见，并在滚动时停留于视口内；高度限制随视口变化，内容较长时可内部滚动。1000px及以下按“文件→流程图→操作”排列，取消吸附，模块网格自适应，不沿用旧图的固定横向最小宽度。

九模块按读取与识别、质量检查、汇总与报告三组展示；阶段连线不表示组内所有模块并行，M06保留M03依赖标识，具体依赖见模块页。未提交、读取中和待确认阶段均为中性框架；确认后显示所选方案，运行后使用实际服务状态。更换文件立即清除旧图的状态、名称与图例。推荐/计划、任务提交与实际运行分别标识。无数据时可直接打开模块说明，不触发推荐或分析任务。

`tests/check-workbench-layout.mjs`检查结构与响应式样式约束；`check-ui-contract.mjs`检查上述状态切换。均不替代浏览器视觉验收。工程说明和历史验证叙述从工作台首屏移除，原内容分别保留在仓库文档和模块详情中。
