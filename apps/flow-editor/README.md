# DBCI-QC 质控流程网页

用于共同维护质控模块、连接关系、输入输出、启用条件和待确认事项。网页编辑的是设计文档，不会修改 DBCI-QC 的算法或运行参数。

## 访问与运行

- **公开展示**：[sunyq19.github.io/DBCI-QC](https://sunyq19.github.io/DBCI-QC/)。无需账号；展示固定发布版。
- **共同编辑**：点击网页右上角“协作编辑”。指定成员登录后编辑、保存或固定版本，仍由现有后端提供服务。
- **更新展示版**：将确认过的流程 JSON 作为新版本加入 `content/releases/publication.json`，提交并推送 GitHub 后执行 `npm run publish:pages`。草稿保存不会直接改动公开发布版。

本项目包含独立的网页与文档存储接口，不依赖质控算法进程。公开展示使用 GitHub Pages；多人保存需要服务端和身份认证，不能仅用静态 Pages 替代。

```bash
# 在 DBCI-QC 仓库根目录
cd apps/flow-editor
npm ci                       # Node.js 24
npm run build:pages
python3 -m http.server 8782 --bind 127.0.0.1 --directory dist-pages
```

打开 `http://127.0.0.1:8782/`。此模式与 GitHub 展示版相同，只读。完整协作服务的本地启动见下文。

## 使用

- 有链接的人可以查看；指定邮箱通过 ChatGPT 登录后可编辑。
- 默认展示“读取与确认 → 单记录/数据集检查 → 汇总与报告”。点模块旁的加号展开子方法；读取方法还可展开具体格式读取器。
- 支持展开全部、收起全部、按模态筛选和跨层级搜索。点击名称查看条件、输入输出、来源；进入编辑后可维护子方法、添加子模块或调整所属层级。
- “连接关系”保留原顶层流程图，支持拖动位置、方向键移动和维护连接。
- “保存”写入共同草稿，并填写修改说明。“固定版本”生成不可变的快照链接。
- 他人先保存时返回冲突，保留当前修改。可导出备份，在新标签查看新版，合并后再保存。
- 历史版本可以复制为新的草稿，原历史和固定链接不会被改写。
- JSON 导出包含完整流程和说明，可再导入；SVG 导出顶层连接关系，用于 PPT 与文档；完整层级保存在 JSON 中。

默认内容来自 2026-11-06 的模块路由设计。M08 评分明确标为待讨论，包含三项试行公式和 23.37 分算例。固定版本表示内容快照，不表示规则已经专家审核。

## 权限与存储

使用 Sites 的 ChatGPT 身份认证。`FLOW_EDITOR_EMAILS` 是服务端邮箱允许列表，放在托管环境变量中，不能写入客户端或源码。逗号、分号或空白分隔；空列表不允许任何人编辑。新增成员需更新此变量并部署；不会自动发送邀请。

公开接口不返回成员邮箱或身份 ID。登录者只在自己的账号菜单看到自己的邮箱。写操作检查身份、编辑名单、同源请求与内容结构。服务端保存作者的站点身份 ID 用于追溯。

共享数据保存在 D1，浏览器 localStorage 不承担共同存储：

- `flow_revisions`：每次保存追加一个完整文档与 SHA-256；不提供覆盖/删除接口。
- `flow_versions`：名称指向固定 revision；不提供覆盖/删除接口。
- 以当前 revision 为前提的单条条件 INSERT 防止并发覆盖；冲突返回 HTTP 409。

这是一人一份本地编辑、保存时合并的协作方式，不是多人实时光标或逐字同步。页面每 25 秒检查是否有新保存。未保存编辑在关闭页面前会提醒，仍建议及时保存或导出。当前没有自动合并和独立自动备份服务；可定期导出 JSON，原始信号和医院资料不放入本站。

## 本地运行

Node.js 24。进入 `apps/flow-editor` 后安装、构建，并仅在首次创建本地库时执行迁移：

```bash
npm run install:ci
npm run build
node --import ./scripts/sites-env.mjs ./node_modules/wrangler/bin/wrangler.js d1 execute DB --local --config dist/server/wrangler.json --persist-to .wrangler/state --file drizzle/0000_high_moonstone.sql
npm run dev -- --port 8782
```

本地 `.dev.vars` 可设置 `FLOW_EDITOR_EMAILS="seedy@sites.test"`，配合 starter 的本机模拟登录。该文件不提交、也不发布；模拟认证不会进入生产构建。生产身份由 Sites 提供。

## 模块目录与内容升级

`content/module-catalog.json` 是从 DBCI-QC 的方法登记、读取器登记及数据集检查文档提取的内容快照。当前含 39 项已接入方法、3 项待接入方法、6 个读取器、11 项资料检查及 3 项执行支持。这里的数量是目录覆盖，不代表科学或临床准确性验证。

```bash
python3 scripts/import-qc-catalog.py /path/to/ephys-qc
```

源文件 SHA-256 随目录保留。更新工具箱代码时需重新核对目录；它不实时跟踪原项目。后台首次升级追加一个含层级的新记录并固定为 `v1.1 · 模块层级`；原 `v1.0` 与成员已有说明保持不变。并发更新使用条件插入，后续访问不会重置团队编辑。

层级信息与节点说明共同保存、导入导出和固定版本。展示分支折叠、搜索和模态筛选不修改共同文档；图上的连接关系仍作用于顶层模块。层级最多五层、总节点最多 250 个。

## 部署说明

- GitHub Pages 从 `gh-pages` 分支根目录发布。首次配置在仓库 Settings → Pages 中选择此分支；当前仓库已配置。
- 在源码提交并推送后执行 `npm run publish:pages`：脚本构建静态文件，在临时目录创建发布提交并正常推送 `gh-pages`，不强制覆盖历史。需要当前账号有仓库推送权限。发布目录只含网页资源和版本信息，不会查询或上传原始脑电数据。
- `.openai/hosting.json` 保留通用存储声明，已移除个人站点 ID。当前协作服务基于 Cloudflare Worker/D1 与 Sites 身份入口；源码包含对应接口。
- 自有服务器部署须提供持久化数据库及可信身份认证。不能直接信任浏览器发送的同名身份请求头。编辑成员名单通过服务端环境变量配置，不提交到 GitHub。
- GitHub Pages 地址无需购买域名；未来绑定自有域名或迁移协作后端时，更新发布配置中的 `editorUrl`。
- 本目录不含登录凭据、成员邮箱、D1 数据库、本地测试记录或脑电原始数据。
